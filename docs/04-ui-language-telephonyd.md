# telephonyd · UI

## telephonyd

> 状态：**原型 ✓**（`telephonyd`，C++23）。两个后端：模拟基带（开发机、QEMU）和 ModemManager（对着模拟的 ModemManager 测过，**未上真机基带**，随 R16）。实现见 [19](19-core-apps.md) §2。

自研电话守护进程，**C++23**，负责通话、短信的收发（存储在 phone-smsd，[32](32-messaging.md)）和网络状态。

```
应用 ──phone.Ui req（tel.* / sms.*）──► Shell broker ──JSON 行──► phone-telephonyd ──► Modem 接口
                                          ▲                          │   ├─ SimModem（开发机、QEMU）
          系统来电界面 · 状态栏信号 · 短信通知 ◄── 事件订阅 ──────────┘   └─ MmModem ──D-Bus──► ModemManager
```

| 项 | 实现 |
|----|------|
| 语言与构建 | C++23（`std::expected`、`std::print`、`std::format`、指定初始化）；CMake；开发机用 GCC 14，Yocto 用 GCC 15 |
| 结构 | 单线程事件循环（`poll` + 定时器）：`loop`、`server`（Unix socket）、`service`（方法与存储）、`modem`（接口与模拟基带）、`mm`（ModemManager 后端）、`json`（自带的小型 JSON 编解码） |
| 选后端 | `--modem sim` / `modemmanager`；不给时读 `--sku` 指向的 `sku.json` 里主板配置的 `modem`（[24](24-sku-framework.md)），设备上的服务就这样启动：QEMU 用模拟基带，骁龙板用 ModemManager |
| 协议 | 与其他系统服务相同：每行一个 JSON，`{id, method, params}` → `{id, ok, err, result}`；客户端调用 `subscribe` 后还会收到事件行。`ussd.initiate`、`ussd.respond` 等网络答复后才回，可能排在之后请求的回复后面，按 `id` 对应 |
| 方法 | `status`、`calls`、`dial`（已有接通的一路时先保持它，新的是第二路，像 GSM 里通话中的 ATD；另一路还在呼叫中或振铃时回 `another call is being set up`，有来电在响时回 `a call is ringing`，已有两路时回 `two calls already`，正在紧急呼叫时回 `an emergency call is in progress`）、`answer`（另一路接通时先保持它：呼叫等待）、`hangup`（`blocked`：拦截名单上的来电，通话记录里记成 `blocked`）、`hold`（`on` 为 false 恢复保持的一路时，接通的另一路随之保持：两路切换）、`mute`、`dtmf`（`call_id`、`tones`：往接通的电话里发按键音，ModemManager 上是 `Call.SendDtmf`）、`log`、`sms.send`（`to`、`text`，`id` 可选：之后的事件用这个 id）、`sms.pending`（phone-smsd 还没确认的事件）、`sms.ack`（`keys`：确认这些事件，telephonyd 放手）、`sms.legacy` / `sms.legacy_drop`（交出、删掉以前自己存的短信）、`sim.unlock`（PIN，或 PUK 加新 PIN）、`sim.pin_lock`（`pin`、`on`：开关 PIN 锁）、`sim.change_pin`（`pin`、`new_pin`，PIN 锁开着时）、`ussd.initiate`、`ussd.respond`、`ussd.cancel`（见 USSD 一行）、`phonebook.read`（见 SIM 卡电话簿一行）、`log.import` / `log.delete`（见导入的通话记录一行）、`roaming.set`（见数据漫游一行）、`apn.list` / `apn.set`（见接入点一行）；测试钩子 `sim.roam`（`net_mcc`、`net_mnc`、`operator`：在这个网络上以漫游注册，号码为空时回到本地网络）、`sim.network`（另可带 `sim_mnc`、`spn`、`gid1`，不带的不变）、`sim.ring`、`sim.sms`（`held`：只放进待确认队列、不发事件，像存下后就崩溃；`data`：8 位短信的用户数据，十六进制，像 WAP 推送；`class`：消息类别，0 是闪信）、`sim.cb`（小区广播：`channel`、`serial`、`text`，`wac`：警报区域坐标，十六进制）、`sim.lock`、`sim.ussd`、`sim.hangup`（`number`：这一路的对方挂断，来电还在响时算未接）、`sim.slow`（`dial_ms`：`dial` 晚这么久才应答，之前这一路还不存在，像晚回 ATD 的基带；`answer_ms`：振铃后对方这么久才接，不给是 900；只给 `dial_ms: 0` 就恢复原样）（只有模拟基带支持） |
| 事件 | `call`（状态变化）、`sms`（收到的短信；发出的短信先报「发送中」，发完再用同一个 id 报「已发送」或「发送失败」，收到送达回执再报「已送达」；除「发送中」外都带 `key`，等 smsd 确认）、`cb`（小区广播，带 `key`）、`status`（注网、信号、SIM 卡状态与剩余次数、`pin_lock` PIN 锁开没开、`imei` 基带的 IMEI，未知时为空）、`unlock`（PIN / PUK 对不对）、`pin`（开关 PIN 锁、改 PIN 成没成）、`ussd`（见 USSD 一行） |
| USSD | `ussd.initiate`（`code`，须符合 `^[*#][0-9*#]{1,30}#$`，如 `*100#`）发码，`ussd.respond`（`text`）回复网络的菜单或提问，都返回 `{state, text}`：`state` 为 `done` 时网络结束了会话，`text` 是最后的答复；为 `input` 时网络在等回复，`text` 是提示或菜单。`ussd.cancel` 结束会话，返回 `{}`，没有会话时什么也不做。同一时间只有一个会话。错误：`invalid code`（码不合格式）、`ussd session open`（已有会话）、`no ussd session`（没有等回复的会话）、`the SIM is locked`（与拨号相同）；ModemManager 后端还有 `no modem that can send USSD`、`not registered on the network` 和 ModemManager 给的错误。事件 `{"event":"ussd","state":…,"text":…}`：网络主动发来的通知（`notify`）或提问（`input`，用 `ussd.respond` 回复），以及网络结束了等回复的会话（`done`，`text` 为空） |
| 射频与移动数据 | `radio.set`（`on`）开关射频（关就是飞行模式），`data.set`（`on`）开关移动数据，都返回 `{}`；两个开关存在 `<state-dir>/telephony/radio.json`，telephonyd 启动时在基带上网之前先用上，所以飞行模式下开机不会先注网。`status` 多了 `radio`、`data`（两个开关）、`data_state`（`connected` / `idle`：开着、还没连上 / `roaming`：在国外、数据漫游关着 / `off`：开关或射频关着）、`data_ifaces`（数据连接能用的网卡，Shell 关移动数据时在防火墙里挡住它们）、`data_apn`（连的接入点，空是网络默认的）和连着时的 `data_ip`：`{iface, mtu, ipv4, ipv6}`，每个地址族是 `{method, address, prefix, gateway, dns}`，`method` 为 `static`（地址、前缀、网关就是这些）、`dhcp`（IPv4 用 DHCP，IPv6 听路由通告）或 `ppp`；Shell 拿它配移动网卡（见下文 Shell 一侧）。另有 SIM 卡和网络的 `sim_mnc`、`net_mnc`、`spn`、`gid1`（十六进制）。射频关着时拨号、发短信、USSD 回 `the radio is off`，没有来电；关射频时进行中的通话以「断开」结束，紧急呼叫中拒关，回 `an emergency call is in progress`。拨紧急号码（112、110、119、120、122、911、999，与 Shell 锁屏能拨的一样）不受射频开关限制：射频关着时 telephonyd 先给它上电再拨，通话的 `emergency` 为 true，Shell 见到就退出飞行模式。紧急号码表见下文「紧急号码」 |
| 接入点 | 各运营商的接入点（APN）是数据：`telephonyd/apns.json`（安卓 `apns-conf.xml` 的 JSON 写法），由 `--apns FILE` 指定，不给时找安装前缀下的 `share/phone/apns.json`，都没有时数据连接用网络默认的接入点。现有中国大陆四家：中国移动（460 00、02、04、07、08、13：上网 `cmnet`，彩信 `cmwap`，IMS `ims`）、中国联通（460 01、06、09：`3gnet`、`3gwap`、`ims`）、中国电信（460 03、05、11：`ctnet`、`ctwap`、`ims`）、中国广电（460 15：`cbnet`、`ims`），IP 类型都是 IPv4/IPv6，取自 AOSP、LineageOS 的 APN 表（**未在真网上核对**）；另有一条按 SPN 区分的：460 01 上 SPN 为「China Telecom」的卡用 `ctnet`（PAP 或 CHAP，用户名 `ctnet@mycdma.cn`），也出自 AOSP 的表。选法：SIM 卡的 MCC、MNC 找运营商，同一网络上有虚拟运营商的条目时，SPN 相同（不分大小写）或 GID1 以它开头的用那一条，否则用网络本身的；数据库里还没有用 GID1 的条目，单元测试用自己的表测。`apn.list` 返回 `{mcc, mnc, spn, carrier, apns, selected, edited}`，每个接入点 `{id, name, apn, types, ip_type, auth, user, password_set, mmsc, mms_proxy, mms_port, edited}`（`types` 有 `default` 上网、`mms`、`ims`、`ia` LTE 附着、`supl`、`xcap`、`emergency`；`auth` 为 `none`、`pap`、`chap`、`pap-chap`），密码从不出 telephonyd；`apn.mms` 回这张 SIM 卡第一个带 `mmsc` 的 mms 类接入点（写法同上，phone-smsd 发收彩信用），没有就回错误；`apn.set` 的 `op`：`save`（`apn`，带 `id` 改那一条，不带就新加，`password` 不给就保留原来的）、`delete`（`id`）、`select`（`id`：用哪个上网接入点，只能选带 `default` 的）、`reset`（回到数据库的），都返回同样的列表。用户第一次改动时把这个运营商（按 MCC、MNC）的列表抄一份，之后改的是这一份，`reset` 删掉它；选中的上网接入点也按运营商记；存在 `<state-dir>/telephony/apns.json`（0600：有密码）。没选过时用第一个带 `default` 的。SIM 卡解锁后、知道它的 MCC 和 MNC 或注上网时，Service 把选中的上网接入点交给基带（`Modem::set_apn`；数据库里没有这张卡时是空的接入点，即网络默认的），基带拿到之前不连数据；换了接入点时断开重连。只连上网的承载：彩信还没有人发（字段留着），IMS（VoLTE）归基带自己 |
| 数据漫游 | `roaming.set`（`on`）开关数据漫游，默认关，和另两个开关一起存在 `radio.json`、开机先用上，所以开机不会先在国外连上数据。漫游按注册状态判断（ModemManager 的 `RegistrationState` 为漫游、仅短信漫游、CSFB 漫游），`status` 的 `roaming`：空（本地或没注网）、`national`（漫游在 SIM 卡本国的别的网络上：MCC 相同，美国 310–316、印度 404–406、日本 440–441、英国 234–235 各算一国；如中国广电的卡在中国移动的网上）、`international`（别国的网络，或任一边的 MCC 不知道）。规则：**国内漫游不受数据漫游开关管**，照常连；国际漫游时开关关着就不连数据承载（已连着的断开），`data_state` 为 `roaming`。香港（454）、澳门（455）、台湾（466）的网络对 460 的卡算国际漫游。状态栏的 R 只在国际漫游时显示 |
| SIM 卡电话簿 | `phonebook.read` 返回 `{contacts: [{index, name, number}]}`：以前的手机存在 SIM 卡上的联系人（EF_ADN），`index` 是卡上的记录号，从 1 起，空记录不列；卡锁着时回 `the SIM is locked`。网络等回复时一样，可能排在之后请求的回复后面。模拟基带的电话簿取自 `sim-network.json` 的 `sim_contacts`；ModemManager 没有电话簿接口，后端用 AT 命令读（见下文）。Shell 用它把 SIM 卡联系人导入通讯录（[19](19-core-apps.md)） |
| 导入的通话记录 | `log.import` 的 `{entries: [{number, dir, result, at, duration}]}`（一次至多 500 条）把另一台手机的通话记录放进来（从旧手机迁移，[36](36-device-switch.md) §7）：每条按 `at` 排进通话记录，记录照旧新的在前，上限 200 条照旧，所以比最新 200 条还早的留不下；号码要合 `dial` 的格式（3–20 个数字、`*`、`#`，`+` 在头），`dir` 为 `in` 时 `result` 是 `answered`、`missed` 或 `rejected`，为 `out` 时是 `outgoing` 或 `busy`，`at` 大于 0；同一号码、方向、时间的已经有了就不再放。返回 `{ids}`，按位置是每条的 id（`i` 加序号，重启后接着编），没放进来的为空；`entries` 不是数组或超过 500 条时报错。导入的条目在 `log` 里多了 `id` 和 `imported: true`。`log.delete` 的 `{ids}` 删掉其中导入的条目（撤销这次导入），本机的通话不动，返回 `{deleted}` |
| 存储 | 通话记录（200 条，导入的带着 `id`、`imported`）和 phone-smsd 还没确认的事件（最多 1000 条）存在 `<state-dir>/telephony/telephony.json`（0600），先写临时文件、`fsync` 再改名；以前存的短信留在里面，直到 smsd 取走（[32](32-messaging.md) §3）；用户改过的接入点在 `apns.json`（0600，同样写法），三个开关在 `radio.json` |
| 权限 | socket 权限 0600，只有 Shell（root）能连；应用只能经 broker |
| 模拟基带 | 已注册「中国移动 4G」，信号 3 格；呼叫中 → 振铃（0.3 秒）→ 通话中（1.2 秒）；号码以 000 结尾返回占线；来电 30 秒无人接听记为未接；每条短信 0.5 秒后报送达、0.8 秒后收到回复（10086 回话费余额），发给 999 结尾号码的发送失败，发给 998 结尾号码的发出去但没有送达回执；`sim.cb` 发一条小区广播；`sim.lock` 让 SIM 卡要 PIN，输错三次转 PUK（12345678）；卡的 PIN 起初是 1234、PIN 锁关着，开关和修改时输错也扣次数，三次后同样转 PUK；IMEI 为 860123456789014（测试用，校验位按 Luhn 算）；USSD 立即答复：`*100#` 答「话费余额 25.80 元，本月剩余流量 3.2 GB。」，`*101#` 给三行菜单「1 查话费」「2 查流量」「3 退出」并等回复，回 1 答「话费余额 25.80 元。」、回 2 答「本月剩余流量 3.2 GB。」、回 3 答「已退出。」，回别的再给一次菜单、前面加一行「输入有误，请重新选择：」，其他码答「网络不支持这个代码。」；`sim.ussd`（`text`、`request`）模拟网络主动发来的 USSD，`request` 为 true 时等回复，回什么都以「已收到。」结束；SIM 卡锁上时结束等回复的会话；SIM 卡是中国移动的 460 00（SPN「中国移动」），所以用数据库的 `cmnet`；数据连接在虚构的网卡 `simwwan0` 上，地址照 QMI 基带经 ModemManager 报的样子给：按接入点的 IP 类型给 IPv4 `100.80.12.34/30`（网关 `100.80.12.33`，DNS `100.80.0.53`、`100.80.0.54`，运营商级 NAT 的地址段）和 IPv6 `2001:db8:4600:12::34/64`（网关 `fe80::1`，文档用的前缀），MTU 1400；`sim.roam` 以漫游注册到别的网络（运营商名不给时显示网络号）。运营商名、短信的自动回复、USSD 的菜单和答复是数据，不在代码里：`telephonyd/sim-network.json`，由 `--network FILE` 指定，不给时找安装前缀下的 `share/phone/sim-network.json`（设备上 `phone-telephonyd` 包装在 `/usr/share/phone/`），都没有时用英文的默认值（运营商 Kario Mobile）；C++ 测试和 ModemManager 的模拟读同一份 |

Shell 一侧（`shell/telephony.go`、`broker_phone.go`）：
- 保持一条订阅连接，telephonyd 重启后自动重连；没有 telephonyd 时状态栏显示「无服务」，其他功能照常。
- SIM 来电不管前台是什么，都由系统全屏接管；接听后交给电话应用；未接来电进通知中心。
- 短信不经这条订阅：phone-smsd 从 telephonyd 收下、存好，Shell 从 smsd 订阅，收到的短信以「短信」应用的名义发通知，应用在运行时还会收到 `sms` 事件（`shell/messaging.go`，[32](32-messaging.md)）。
- 没有 `phone` 权限的应用请求拨号时，系统先弹窗让用户确认；通话界面始终归电话应用。
- 发不出去的短信，短信应用标「未发出」、可以重发，系统也以短信应用的名义发通知。
- SIM 卡要 PIN（或 PUK 加新 PIN）时，系统画一个和支付确认同类的界面要码，数字只经 Shell 交给 telephonyd 和 SIM 卡，应用拿不到；输错显示还剩几次，返回键可以稍后再输（SIM 卡状态变了或有人拨号时再出现）；状态栏和待机界面显示「SIM 已锁」「无 SIM 卡」。
- 飞行模式、移动数据和数据漫游由 Shell 做主（`shell/airplane.go`，[11](11-platform-architecture.md) §16）：Shell 每次连上 telephonyd 都把它的三个开关对齐到系统设置；飞行模式下拨非紧急号码由 Shell 直接拒绝（「飞行模式已打开，关闭后才能打电话」）。设置的接入点页经 `apn.list`、`apn.set` 能力（只给系统应用）由 Shell 原样转给 telephonyd（`shell/apn.go`），日志里只有操作和 id。
- 移动网卡的地址（`shell/cellnet.go`）：设备上（root、有 systemd-networkd）Shell 按 `data_ip` 给网卡写一个 networkd 的运行时配置 `/run/systemd/network/10-kario-cell-<网卡>.network`，`networkctl reload` 后让它重新配置：静态的 IPv4、IPv6 地址照写，网关是 `[Route]`（`GatewayOnLink`），没有网关的 IPv4（点对点）默认路由就是网卡本身；`dhcp` 的 IPv4 用 networkd 的 DHCP；IPv6 一律听路由通告（SLAAC），只给了链路本地地址时用它的接口标识做 `Token=static:`；DNS 写进去，networkd 交给 systemd-resolved 管这块网卡；MTU 照写（有 IPv6 时不低于 1280）；路由的跃点是 2048，排在 iwd 的 Wi-Fi 和 networkd 的 DHCP 默认值（1024）后面，Wi-Fi、有线连着时它们优先。写进文件的每个值都是解析过、按自己的格式写回的，网卡名另外核对，telephonyd 给的东西到不了配置的文本里；PPP 和还没有地址的不配。数据断开（关移动数据、国际漫游时没开数据漫游、承载断了）时文件改成 `Unmanaged=yes`（挡住 QEMU 的 `ip=dhcp` 那种匹配所有网卡的配置），清掉网卡的地址、把它关掉（networkd 不管的网卡它原样留着）；Shell 重启后接管上一个 Shell 留在 `/run` 里的文件。开发机（不是 root、没有 networkd）什么也不配。生成的文件和拆除由单元测试覆盖；模拟器上的用例（veth 顶替 `simwwan0`）两个镜像上 ✓；**未上真机**。
- 「设置 › SIM 卡锁」开关 PIN 锁、修改 PIN 码：设置应用只请求（`settings.set` 的 `sim_pin_lock`、`sim_pin_change`），PIN 码在同一类系统界面上输入（修改时输现在的、新的、再输一次新的），只交给 telephonyd 和 SIM 卡；设置应用等到结果（成了、输错了、用户取消）才收到回复。输错三次 SIM 卡自己锁上，转到要 PUK 的解锁界面。

**ModemManager 后端**（`src/mm.cpp`）：实现同一个 `Modem` 接口，经 sd-bus 调系统总线上的 `org.freedesktop.ModemManager1`（1.20 起的接口），只多依赖 libsystemd。Yocto 构建强制编进（缺 libsystemd 就构建失败，不会悄悄只剩模拟基带）；开发机没有 libsystemd 时不编。
- **跟随**：ModemManager 起来、退出（`NameOwnerChanged`），基带出现、移除（ObjectManager）；用报上来的第一个基带。基带处于禁用状态时由 telephonyd 启用它（ModemManager 自己不启用）。基带或 ModemManager 消失时，进行中的通话以「断开」结束，状态变为未注册。
- **状态**：取自 Modem 与 Modem3gpp 的属性——本地、漫游、仅短信都算已注册；运营商名；制式按 AccessTechnologies 归成 2G–5G；信号百分比折成 0–4 格；本机号码；IMEI 取 Modem 的 `EquipmentIdentifier`。有变化就发 `status` 事件。
- **通话**：`Voice.CreateCall` 加 `Call.Start` 拨出，`Accept` 接听，`Hangup` 挂断。ModemManager 没有单路保持，保持和恢复都用 `HoldAndAccept`，对单路通话它正好就是保持和恢复；通话中接第二路来电（呼叫等待）也用它；通话中拨第二路时先 `HoldAndAccept`（没有等待、保持的通话时它只保持接通的那一路），保持了再 `CreateCall`，模拟的 ModemManager 上 `mm_test.py` 的 `outgoing_call` 测过（先 `HoldAndAccept` 后 `CreateCall`、两路时不能再拨、切换回第一路），**未上真机**。`Call.StateChanged` 换成 telephonyd 的状态；结束原因按谁挂的、接通过没有、网络给的原因，归成挂断 / 拒接 / 占线 / 未接 / 失败 / 对方挂断。结束的通话从 ModemManager 删掉。静音属于音频通路（音频服务，R29），后端只记状态。
- **SIM 卡**：卡锁着时 ModemManager 停在 LOCKED，`UnlockRequired` 说要 PIN 还是 PUK、`UnlockRetries` 给剩余次数；`sim.unlock` 调 Sim 对象的 `SendPin` / `SendPuk`，解锁后基带回到禁用状态，telephonyd 接着启用它。卡锁着时拨号、发短信直接拒绝。开关 PIN 锁调 `EnablePin`，修改调 `ChangePin`；PIN 锁开没开读 3GPP 接口的 `EnabledFacilityLocks`（第 0 位是 SIM 卡）。
- **短信**：`Messaging.Create`（要送达回执）加 `Sms.Send` 发送，先报「发送中」，`Send` 返回后报「已发送」或「发送失败」；之后 `DeliveryState` 变了报「已送达」或「发送失败」（网络还在重试时不报），再从基带删掉，等回执的最多 64 条。收到的短信要等分段收齐（状态 RECEIVED）才算到，id 由号码、短信中心时间戳和内容算出（重启后不变）；它留在基带里，phone-smsd 确认（`sms.ack`）后才删，SIM 卡那几十条的空间不会占满，任何一边重启也丢不了；telephonyd 启动前就存在基带或 SIM 卡里的短信也这样交出去。没对上已发短信的送达报告直接删掉。时间用短信中心的时间戳。
- **小区广播**：ModemManager 1.24 的 `Modem.CellBroadcast`：设频道 4352–4359、4370–4400，收 `Added` 和 `Cbm` 对象（收齐才算到），报 `cb` 事件，smsd 确认后 `Delete`（[32](32-messaging.md) §7）；对着模拟的 ModemManager 测过（`cell_broadcast` 用例），**未上真机**。
- **USSD**：基带对象上 `Modem3gpp.Ussd` 的 `Initiate`、`Respond`、`Cancel`。`Initiate` / `Respond` 返回网络的答复后，再读一次会话的 `State`（它的 PropertiesChanged 可能晚于答复到），为 3（等用户回复）报 `input`，否则报 `done`。网络主动发来的 USSD 是 `NetworkNotification`、`NetworkRequest` 属性的变化，报 `ussd` 事件 `notify`、`input`；等回复时 `State` 回到空闲（网络结束会话），或基带、ModemManager 消失，报 `done`。基带没有 Ussd 接口、卡锁着、没注册时直接拒绝。
- **射频与移动数据**：关射频先 `Modem.Enable(false)`（ModemManager 随之结束通话和数据承载），再 `SetPowerState` 到低功耗（2）；开射频先 `SetPowerState` 到开（3），再照常启用。射频关着时 telephonyd 不再自动启用基带。射频关着拨紧急号码时先这样开，基带启用后再 `CreateCall`。移动数据开着、已注册、Service 给了接入点、没有国际漫游被挡住、没有连着的承载时，`Modem.Simple.Connect` 连上，属性是 `apn`、`ip-type`（`MMBearerIpFamily`：IPv4 1、IPv6 2、IPv4v6 4；网络默认的空接入点不给，由 ModemManager 选）、`apn-type`（上网，2）、`allow-roaming`（telephonyd 判断能连时为真：数据漫游开着或国内漫游；本地连的承载为假，漫游时 ModemManager 自己断掉它，telephonyd 再按规则连），认证不是 `none` 时加 `allowed-auth`（`MMBearerAllowedAuth`：PAP 2、CHAP 4、两者 6）、`user`、`password`；失败了等注册状态、开关或接入点变了再试；关掉时、国际漫游而数据漫游关着时、连着的承载用的是别的接入点（承载 `Properties` 的 `apn`）时 `Simple.Disconnect`（全部承载），断开后再按新的接入点连；承载的接入点和要的不同时 `data_state` 是 `idle`。读到 SIM 卡（它的接入点）和已有承载的状态之前什么也不连，读到 SIM 卡之前也不因接入点不同断开已有的承载：telephonyd 重启时连着的承载留着，不会先用网络默认的接入点另连一个。SIM 卡的 SPN、GID1 取 Sim 的 `OperatorName`、`Gid1`（字节数组，写成十六进制），网络的 MNC 取 `OperatorCode`；SIM 卡换了或基带消失时忘掉接入点，等 Service 再给。`data_ip` 取连着的承载的 `Interface`、`Ip4Config`、`Ip6Config`（`method` 1 PPP、2 静态、3 DHCP，`address`、`prefix`、`gateway`、`dns1`–`dns3`、`mtu`）。`data_ifaces` 取基带的网络口（`Ports` 里类型为 net 的）和承载的 `Interface`。模拟的 ModemManager 上的用例 `mobile_data`（数据库的 `cmnet`、承载的地址）、`apn_change`（改接入点后断开重连、`reset`）、`data_roaming`（国际漫游时不连、打开数据漫游后带 `allow-roaming` 连上、国内漫游照常）、`airplane_mode` 通过（`make mm-selftest`）；初始附着（`ia`）的接入点没有交给 `Modem3gpp.SetInitialEpsBearerSettings`（**未实现**：基带附着时用它自己的设置，多半是网络默认的）；漫游时另用一种 IP 类型（安卓的 `roaming_protocol`）**未实现**；真网上的承载和地址**未上真机**。
- **SIM 卡电话簿**：ModemManager 只有存储位置的枚举，没有读电话簿的接口，后端经 `Modem.Command` 发 AT 命令（3GPP TS 27.007）：记下 `AT+CSCS?` 的字符集，切到 `UCS2`（什么文字的名字都不乱码），`AT+CPBS="SM"` 选 SIM 卡的电话簿，`AT+CPBR=?` 查记录范围，`AT+CPBR=<首>,<末>` 读出，最后把字符集改回去。号码也按 UCS2 发来的基带，解出来是号码才用；类型 145 的号码补上 `+`；空电话簿报 not found 的基带算作没有联系人。`Modem.Command` 要 ModemManager 带 `--debug` 运行才收，不然回 `the modem takes no AT commands (ModemManager needs --debug)`；镜像里还没装 ModemManager（随硬件机型的配方加上，到时要开 `--debug`），**未上真机**。高通基带也可以经 QMI 的 UIM 服务读 EF_ADN，**未实现**。
- **不被基带拖住**：所有 D-Bus 请求都异步，事件循环不会因此阻塞；等网络的请求（发短信、接听、启用、USSD）超时 120 秒；系统总线断开时 telephonyd 退出，由 systemd 重启。
- **测试**：`make mm-selftest` 在 Debian 容器里起一条私有 D-Bus 和一个 Python 写的模拟 ModemManager（`test/mock_mm.py`，导出同样的对象、属性和信号，另带一个控制接口扮演网络），通过 telephonyd 的 socket 跑 35 个用例：启用并注册、SIM 卡里的旧短信等确认才删、IMEI、去电、占线、来电接听 / 拒接 / 未接、保持与恢复、静音、按键音、SIM 卡电话簿（没开 `--debug` 时报错、读出、字符集改回去、空电话簿）、呼叫等待、发短信和送达回执、没有回执的短信留着等、网络拒发、分段短信只投递一次、没确认的短信 telephonyd 重启后还在（连着的承载也留着）、小区广播、信号与制式变化、USSD 查询（一次答完、菜单与回复、网络主动发来的通知与提问、取消、网络结束会话）、SIM 卡 PIN（输错、输对）、PUK、在设置里改 PIN 和关 PIN 锁（输错、改完）、移动数据（数据库的接入点、承载的地址）、改接入点、数据漫游、飞行模式、通话中基带消失又回来、ModemManager 重启、错误参数。
- **紧急号码**：默认是 112、110、119、120、122、911、999，再加上 SIM 卡给的（ModemManager 的 `Sim.EmergencyNumbers`，模拟基带从 `sim-network.json` 的 `emergency_numbers` 读），`status` 的 `emergency_numbers` 告诉 Shell；SIM 卡锁着时紧急号码照样拨出（3GPP TS 22.101），别的号码拒绝；Shell 的 SIM 卡 PIN 界面上输入紧急号码按通话键就拨出，锁屏和飞行模式下也一样。单元测试和模拟的 ModemManager 上 ✓，**未上真机**；没插 SIM 卡时的真机行为要看基带，**未上真机**。
- **未实现**：VoLTE / IMS 注册状态；真机上 ModemManager 与高通用户态（QRTR、rmtfs、基带固件）的集成，随 R16。
