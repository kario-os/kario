# telephonyd · UI

## telephonyd

> 状态：**原型 ✓**（`telephonyd`，C++23）。两个后端：模拟基带（开发机、QEMU）和 ModemManager（对着模拟的 ModemManager 测过；一加 6T 上接真基带跑过：移动数据连上了，电话没打通，修了**未上真机**，其余**未上真机**，见下文「真机」一条）。实现见 [19](19-core-apps.md) §2。

自研电话守护进程，**C++23**，负责通话、短信的收发（存储在 phone-smsd，[32](32-messaging.md)）和网络状态。

```
应用 ──phone.Ui req（tel.* / sms.*）──► Shell broker ──JSON 行──► phone-telephonyd ──► Modem 接口
                                          ▲                          │   ├─ SimModem（开发机、QEMU）
          系统来电界面 · 状态栏信号 · 短信通知 ◄── 事件订阅 ──────────┘   └─ MmModem ──D-Bus──► ModemManager
```

| 项 | 实现 |
|----|------|
| 语言与构建 | C++23（`std::expected`、`std::print`、`std::format`、指定初始化）；CMake；开发机用 GCC 14，Yocto 用 GCC 15 |
| 结构 | 单线程事件循环（`poll` + 定时器）：`loop`、`server`（Unix socket）、`service`（方法与存储）、`modem`（接口与模拟基带）、`mm`（ModemManager 后端）、`json`（自带的小型 JSON 编解码） |
| 选后端 | `--modem sim` / `modemmanager`；不给时读 `--sku` 指向的 `sku.json` 里主板配置的 `modem`（[24](24-sku-framework.md)），设备上的服务就这样启动：QEMU 用模拟基带，骁龙板用 ModemManager。编进的后端按名字列在 `src/backend.cpp`（没编进的名字退出码 2），和 `tools/sku.py` 的 `MODEMS` 一致；后端要守的契约、SoC 胶水和联发科的设计见 [24](24-sku-framework.md) §8.8、§8.9 |
| 协议 | 与其他系统服务相同：每行一个 JSON，`{id, method, params}` → `{id, ok, err, result}`；客户端调用 `subscribe` 后还会收到事件行。`ussd.initiate`、`ussd.respond` 等网络答复后才回，可能排在之后请求的回复后面，按 `id` 对应 |
| 方法 | `status`、`calls`、`dial`（已有接通的一路时先保持它，新的是第二路，像 GSM 里通话中的 ATD；另一路还在呼叫中或振铃时回 `another call is being set up`，有来电在响时回 `a call is ringing`，已有两路时回 `two calls already`，正在紧急呼叫时回 `an emergency call is in progress`）、`answer`（另一路接通时先保持它：呼叫等待）、`hangup`（`blocked`：拦截名单上的来电，通话记录里记成 `blocked`）、`hold`（`on` 为 false 恢复保持的一路时，接通的另一路随之保持：两路切换）、`mute`、`dtmf`（`call_id`、`tones`：往接通的电话里发按键音，ModemManager 上是 `Call.SendDtmf`；通话的 `dtmf` 只留最近发的 64 个，`kMaxDtmf`）、`log`、`sms.send`（`to`、`text`，`id` 可选：之后的事件用这个 id）、`sms.pending`（phone-smsd 还没确认的事件）、`sms.ack`（`keys`：确认这些事件，telephonyd 放手）、`sms.legacy` / `sms.legacy_drop`（交出、删掉以前自己存的短信）、`sim.unlock`（PIN，或 PUK 加新 PIN）、`sim.pin_lock`（`pin`、`on`：开关 PIN 锁）、`sim.change_pin`（`pin`、`new_pin`，PIN 锁开着时）、`ussd.initiate`、`ussd.respond`、`ussd.cancel`（见 USSD 一行）、`phonebook.read`（见 SIM 卡电话簿一行）、`log.import` / `log.delete`（见导入的通话记录一行）、`roaming.set`（见数据漫游一行）、`apn.list` / `apn.set`（见接入点一行）、`mms.connect` / `mms.disconnect`（见彩信承载一行）；测试钩子 `sim.roam`（`net_mcc`、`net_mnc`、`operator`：在这个网络上以漫游注册，号码为空时回到本地网络）、`sim.ims`（`state`：注册着时 `status` 报的 IMS 注册状态，起初是 `unknown`）、`sim.network`（另可带 `sim_mnc`、`spn`、`gid1`，不带的不变）、`sim.ring`、`sim.sms`（`held`：只放进待确认队列、不发事件，像存下后就崩溃；`data`：8 位短信的用户数据，十六进制，像 WAP 推送；`class`：消息类别，0 是闪信）、`sim.cb`（小区广播：`channel`、`serial`、`text`，`wac`：警报区域坐标，十六进制）、`sim.lock`、`sim.ussd`、`sim.hangup`（`number`：这一路的对方挂断，来电还在响时算未接）、`sim.slow`（`dial_ms`：`dial` 晚这么久才应答，之前这一路还不存在，像晚回 ATD 的基带；`answer_ms`：振铃后对方这么久才接，不给是 900；只给 `dial_ms: 0` 就恢复原样）（只有模拟基带支持） |
| 事件 | `call`（状态变化）、`sms`（收到的短信；发出的短信先报「发送中」，发完再用同一个 id 报「已发送」或「发送失败」，收到送达回执再报「已送达」；除「发送中」外都带 `key`，等 smsd 确认）、`cb`（小区广播，带 `key`）、`status`（注网、信号、SIM 卡状态与剩余次数、`pin_lock` PIN 锁开没开、`imei` 基带的 IMEI，未知时为空，`ims` IMS（VoLTE）注册状态，见 ModemManager 一节的「通话」）、`unlock`（PIN / PUK 对不对）、`pin`（开关 PIN 锁、改 PIN 成没成）、`ussd`（见 USSD 一行） |
| USSD | `ussd.initiate`（`code`，须符合 `^[*#][0-9*#]{1,30}#$`，如 `*100#`）发码，`ussd.respond`（`text`）回复网络的菜单或提问，都返回 `{state, text}`：`state` 为 `done` 时网络结束了会话，`text` 是最后的答复；为 `input` 时网络在等回复，`text` 是提示或菜单。`ussd.cancel` 结束会话，返回 `{}`，没有会话时什么也不做。同一时间只有一个会话。错误：`invalid code`（码不合格式）、`ussd session open`（已有会话）、`no ussd session`（没有等回复的会话）、`the SIM is locked`（与拨号相同）；ModemManager 后端还有 `no modem that can send USSD`、`not registered on the network` 和 ModemManager 给的错误。事件 `{"event":"ussd","state":…,"text":…}`：网络主动发来的通知（`notify`）或提问（`input`，用 `ussd.respond` 回复），以及网络结束了等回复的会话（`done`，`text` 为空） |
| 射频与移动数据 | `radio.set`（`on`）开关射频（关就是飞行模式），`data.set`（`on`）开关移动数据，都返回 `{}`；两个开关存在 `<state-dir>/telephony/radio.json`，telephonyd 启动时在基带上网之前先用上，所以飞行模式下开机不会先注网。`status` 多了 `radio`、`data`（两个开关）、`data_state`（`connected` / `idle`：开着、还没连上 / `roaming`：漫游中、漫游开关不让连，见「数据漫游」一行 / `off`：开关或射频关着）、`data_ifaces`（数据连接能用的网卡，移动数据关着或漫游开关不让连时 Shell 在防火墙里挡住它们）、`data_apn`（连的接入点，空是网络默认的）和连着时的 `data_ip`：`{iface, mtu, ipv4, ipv6}`，每个地址族是 `{method, address, prefix, gateway, dns}`，`method` 为 `static`（地址、前缀、网关就是这些）、`dhcp`（IPv4 用 DHCP，IPv6 听路由通告）或 `ppp`；Shell 拿它配移动网卡（见下文 Shell 一侧）。另有 SIM 卡和网络的 `sim_mnc`、`net_mnc`、`spn`、`gid1`（十六进制）。射频关着时拨号、发短信、USSD 回 `the radio is off`，没有来电；关射频时进行中的通话以「断开」结束，紧急呼叫中拒关，回 `an emergency call is in progress`。拨紧急号码（112、110、119、120、122、911、999，与 Shell 锁屏能拨的一样）不受射频开关限制：射频关着时 telephonyd 先给它上电再拨，通话的 `emergency` 为 true，Shell 见到就退出飞行模式。紧急号码表见下文「紧急号码」 |
| 接入点 | 各运营商的接入点（APN）是数据：`telephonyd/apns.json`（安卓 `apns-conf.xml` 的 JSON 写法），由 `--apns FILE` 指定，不给时找安装前缀下的 `share/phone/apns.json`，都没有时数据连接用网络默认的接入点。现有中国大陆四家：中国移动（460 00、02、04、07、08、13：上网 `cmnet`，彩信 `cmwap`，IMS `ims`）、中国联通（460 01、06、09：`3gnet`、`3gwap`、`ims`）、中国电信（460 03、05、11：`ctnet`、`ctwap`、`ims`）、中国广电（460 15：`cbnet`、`ims`），IP 类型都是 IPv4/IPv6，取自 AOSP、LineageOS 的 APN 表（**未在真网上核对**）；另有一条按 SPN 区分的：460 01 上 SPN 为「China Telecom」的卡用 `ctnet`（PAP 或 CHAP，用户名 `ctnet@mycdma.cn`），也出自 AOSP 的表。选法：SIM 卡的 MCC、MNC 找运营商，同一网络上有虚拟运营商的条目时，SPN 相同（不分大小写）或 GID1 以它开头的用那一条，否则用网络本身的；数据库里还没有用 GID1 的条目，单元测试用自己的表测。`apn.list` 返回 `{mcc, mnc, spn, carrier, apns, selected, edited}`，每个接入点 `{id, name, apn, types, ip_type, auth, user, password_set, mmsc, mms_proxy, mms_port, edited}`（`types` 有 `default` 上网、`mms`、`ims`、`ia` LTE 附着、`supl`、`xcap`、`emergency`；`auth` 为 `none`、`pap`、`chap`、`pap-chap`），密码从不出 telephonyd；`apn.mms` 回这张 SIM 卡第一个带 `mmsc` 的 mms 类接入点（写法同上，phone-smsd 发收彩信用），没有就回错误；`apn.set` 的 `op`：`save`（`apn`，带 `id` 改那一条，不带就新加，`password` 不给就保留原来的；一张卡的列表连数据库里的至多 32 个，`kMaxApns`，满了新加的回 `a SIM has at most 32 APNs: delete one first`，改的照样行）、`delete`（`id`）、`select`（`id`：用哪个上网接入点，只能选带 `default` 的）、`reset`（回到数据库的），都返回同样的列表。用户第一次改动时把这个运营商（按 MCC、MNC）的列表抄一份，之后改的是这一份，`reset` 删掉它；选中的上网接入点也按运营商记；存在 `<state-dir>/telephony/apns.json`（0600：有密码）。没选过时用第一个带 `default` 的。SIM 卡解锁后、知道它的 MCC 和 MNC 或注上网时，Service 把选中的上网接入点交给基带（`Modem::set_apn`；数据库里没有这张卡时是空的接入点，即网络默认的），基带拿到之前不连数据；换了接入点时断开重连（别的接入点，或同一个接入点改了 IP 类型、认证、用户名、密码；只改名字不算）。Service 交给基带的其实是这张卡的接入点计划（`ApnList::plan`）：上网接入点；LTE 初始附着的接入点（选中的上网接入点带 `ia` 时用它，否则第一个带 `ia` 的，都没有时基带用自己的设置）；彩信接入点（`apn.mms` 那一条；和上网接入点名字相同、不分大小写时没有，彩信走数据连接）；IMS 和紧急接入点的名字（别的程序为 VoLTE 开的承载，telephonyd 认出来不碰，见下文 ModemManager 一节）。phone-smsd 发收彩信时经 `apn.mms` 拿彩信中心和代理；彩信放在单独接入点上时（如中国移动的 cmwap 和 cmnet）telephonyd 给它另连一条承载，见「彩信承载」一行 |
| 彩信承载 | `mms.connect`：phone-smsd 每次收发彩信前调用。没有单独的彩信接入点时回 `{shared: true}`，彩信走数据连接；否则在彩信接入点上另连一条承载（ModemManager 后端：`Simple.Connect`，`apn-type` 为彩信 8，网卡和数据承载的不同），连上、有了地址再回 `{shared: false, iface, mtu, ipv4, ipv6}`（写法同 `data_ip`），这时 `status` 里也有 `mms_link`；从每次调用起保持三分钟，`mms.disconnect` 立即放掉（`Simple.Disconnect` 只断这一条）。和数据连接受同样的开关管：移动数据或射频关着回 `mobile data is off`，漫游开关不让连时回 `roaming where mobile data may not be up`，没注网回 `not registered on the network`，连不上回 ModemManager 的错误；连着时关掉移动数据，它随数据承载一起断开。`data_ifaces` 带上它的网卡（流量算移动数据）。模拟基带的彩信一律走数据连接。Shell 给它的网卡另配地址和只管它的路由（见下文 Shell 一侧），phone-smsd 的连接从它的地址出去（[32](32-messaging.md) §11）。对着模拟的 ModemManager 测过，**未上真机** |
| 数据漫游 | `roaming.set`（`on`、`national`）开关数据漫游和国内漫游：数据漫游默认关，国内漫游默认开，不给 `national` 时国内漫游不变；两个开关和另两个开关一起存在 `radio.json`、开机先用上，所以开机不会先在国外连上数据。漫游按注册状态判断（ModemManager 的 `RegistrationState` 为漫游、仅短信漫游、CSFB 漫游），`status` 的 `roaming`：空（本地或没注网）、`national`（漫游在 SIM 卡本国的别的网络上：MCC 相同，美国 310–316、印度 404–406、日本 440–441、英国 234–235 各算一国；如中国广电的卡在中国移动的网上）、`international`（别国的网络，或任一边的 MCC 不知道）；`data_roaming`、`national_roaming` 是两个开关。规则（`roaming_allowed`）：国际漫游归数据漫游开关管，国内漫游归国内漫游开关管，各管各的（数据漫游开着、国内漫游关着时，国内漫游也不连）；开关不让连时不连数据承载（已连着的断开），`data_state` 为 `roaming`。香港（454）、澳门（455）、台湾（466）的网络对 460 的卡算国际漫游。状态栏的 R 只在国际漫游时显示 |
| SIM 卡电话簿 | `phonebook.read` 返回 `{contacts: [{index, name, number}]}`：以前的手机存在 SIM 卡上的联系人（EF_ADN），`index` 是卡上的记录号，从 1 起，空记录不列；卡锁着时回 `the SIM is locked`。网络等回复时一样，可能排在之后请求的回复后面。模拟基带的电话簿取自 `sim-network.json` 的 `sim_contacts`；ModemManager 没有电话簿接口，后端用 AT 命令读（见下文）。Shell 用它把 SIM 卡联系人导入通讯录（[19](19-core-apps.md)） |
| 导入的通话记录 | `log.import` 的 `{entries: [{number, dir, result, at, duration}]}`（一次至多 500 条）把另一台手机的通话记录放进来（从旧手机迁移，[36](36-device-switch.md) §7）：每条按 `at` 排进通话记录，记录照旧新的在前，上限 200 条照旧，所以比最新 200 条还早的留不下；号码要合 `dial` 的格式（3–20 个数字、`*`、`#`，`+` 在头），`dir` 为 `in` 时 `result` 是 `answered`、`missed` 或 `rejected`，为 `out` 时是 `outgoing` 或 `busy`，`at` 大于 0；同一号码、方向、时间的已经有了就不再放。返回 `{ids}`，按位置是每条的 id（`i` 加序号，重启后接着编），没放进来的为空；`entries` 不是数组或超过 500 条时报错。导入的条目在 `log` 里多了 `id` 和 `imported: true`。`log.delete` 的 `{ids}` 删掉其中导入的条目（撤销这次导入），本机的通话不动，返回 `{deleted}` |
| 存储 | 通话记录（200 条，导入的带着 `id`、`imported`）和 phone-smsd 还没确认的事件（最多 1000 条）存在 `<state-dir>/telephony/telephony.json`（0600），先写临时文件、`fsync` 再改名；以前存的短信留在里面，直到 smsd 取走（[32](32-messaging.md) §3）；用户改过的接入点在 `apns.json`（0600，同样写法），三个开关在 `radio.json` |

Shell 一侧（`shell/telephony.go`、`broker_phone.go`）：
- 保持一条订阅连接，telephonyd 重启后自动重连；没有 telephonyd 时状态栏显示「无服务」，其他功能照常。
- SIM 来电不管前台是什么，都由系统全屏接管；接听后交给电话应用；未接来电进通知中心。
- 短信不经这条订阅：phone-smsd 从 telephonyd 收下、存好，Shell 从 smsd 订阅，收到的短信以「短信」应用的名义发通知，应用在运行时还会收到 `sms` 事件（`shell/messaging.go`，[32](32-messaging.md)）。
- 没有 `phone` 权限的应用请求拨号时，系统先弹窗让用户确认；通话界面始终归电话应用。
- 发不出去的短信，短信应用标「未发出」、可以重发，系统也以短信应用的名义发通知。
- SIM 卡要 PIN（或 PUK 加新 PIN）时，系统画一个和支付确认同类的界面要码，数字只经 Shell 交给 telephonyd 和 SIM 卡，应用拿不到；输错显示还剩几次，返回键可以稍后再输（SIM 卡状态变了或有人拨号时再出现）；状态栏和待机界面显示「SIM 已锁」「无 SIM 卡」。
- VoLTE（`shell/airplane.go`）：在 4G 或 5G 上注册着、`status` 的 `ims` 是 `registered` 时，状态栏在网络类型左边写「VoLTE」，有没有移动数据都一样（phone-paint 用常规字重；状态栏放不下时不画，如 12 键直板机的窄屏中间写着通话时）；`radio.state` 的 `ims` 把注册状态交给应用（[22](22-developer-api.md)），「设置 › 移动网络」最后一行「VoLTE」用文字写出：已注册、正在注册…、未注册、受限、未知（只显示，不进设置首页这一组的摘要）。telephonyd 不报 `ims` 时当 `unknown`。**未上真机**（[39](39-oneplus-6t.md) §14.21）。
- 飞行模式、移动数据、数据漫游和国内漫游由 Shell 做主（`shell/airplane.go`，[11](11-platform-architecture.md) §16）：Shell 每次连上 telephonyd 都把它的开关对齐到系统设置；移动数据开着而漫游开关不让连（`data_state` 为 `roaming`）时，防火墙像关移动数据时一样挡住 `data_ifaces`，并以「设置」的名义通知「漫游时没有移动数据」，写明手机在哪个网络上、要打开哪个开关，点开是「设置 › 移动网络」，漫游结束、开关打开或移动数据关掉时通知随之消失；飞行模式下拨非紧急号码由 Shell 直接拒绝（「飞行模式已打开，关闭后才能打电话」）。设置的接入点页经 `apn.list`、`apn.set` 能力（只给系统应用）由 Shell 原样转给 telephonyd（`shell/apn.go`），日志里只有操作和 id。
- 移动网卡的地址（`shell/cellnet.go`）：设备上（root、有 systemd-networkd）Shell 按 `data_ip` 给网卡写一个 networkd 的运行时配置 `/run/systemd/network/10-kario-cell-<网卡>.network`，`networkctl reload` 后让它重新配置：静态的 IPv4、IPv6 地址照写，网关是 `[Route]`（`GatewayOnLink`），没有网关的 IPv4（点对点）默认路由就是网卡本身；`dhcp` 的 IPv4 用 networkd 的 DHCP；IPv6 一律听路由通告（SLAAC），只给了链路本地地址时用它的接口标识做 `Token=static:`；DNS 写进去，networkd 交给 systemd-resolved 管这块网卡；MTU 照写（有 IPv6 时不低于 1280）；路由的跃点是 2048，排在 iwd 的 Wi-Fi 和 networkd 的 DHCP 默认值（1024）后面，Wi-Fi、有线连着时它们优先。写进文件的每个值都是解析过、按自己的格式写回的，网卡名另外核对，telephonyd 给的东西到不了配置的文本里；PPP 和还没有地址的不配。数据断开（关移动数据、国际漫游时没开数据漫游、承载断了）时文件改成 `Unmanaged=yes`（挡住 QEMU 的 `ip=dhcp` 那种匹配所有网卡的配置），清掉网卡的地址、把它关掉（networkd 不管的网卡它原样留着）；Shell 重启后接管上一个 Shell 留在 `/run` 里的文件；用模拟基带的 Shell（自测的，telephonyd 报的 `backend` 是 `sim`）只接管模拟网卡 `simwwan0` 的，手机自己的 Shell 给真基带网卡写的不碰（一加 6T 上自测的 Shell 拿下过 `qmapmux0.0` 和默认路由，[39](39-oneplus-6t.md) §16.10）。开发机（不是 root、没有 networkd）什么也不配。生成的文件和拆除由单元测试覆盖；模拟器上的用例（veth 顶替 `simwwan0`）两个镜像上 ✓；**未上真机**。彩信承载（`mms_link`，移动数据开着时）另写一个同样前缀的文件：只配它的 IPv4 地址（要静态的：下面的规则按地址匹配；不是静态的不配，记一行日志），不开 IPv6、`DNSDefaultRoute=no`、不写 DNS（不进 systemd-resolved）；路由放进它自己的表 2049，一条策略规则（`From=<地址>/32`，优先级 29999，排在 VPN 的 30000、30001 前面，开着 VPN 时彩信也走自己的接入点）让从这个地址出去的包查这张表，所以只有 phone-smsd 从这个地址发出的连接走彩信承载，主表和默认路由都不变；承载放掉后文件同样改成 `Unmanaged=yes`。网卡和数据承载的相同时不另配。生成的文件由单元测试覆盖，**未上真机**；VPN 的锁定模式（只许经隧道出去）会不会挡住它**未验证**。
- 「设置 › SIM 卡锁」开关 PIN 锁、修改 PIN 码：设置应用只请求（`settings.set` 的 `sim_pin_lock`、`sim_pin_change`），PIN 码在同一类系统界面上输入（修改时输现在的、新的、再输一次新的），只交给 telephonyd 和 SIM 卡；设置应用等到结果（成了、输错了、用户取消）才收到回复。输错三次 SIM 卡自己锁上，转到要 PUK 的解锁界面。

**ModemManager 后端**（`src/mm.cpp`）：实现同一个 `Modem` 接口，经 sd-bus 调系统总线上的 `org.freedesktop.ModemManager1`（1.20 起的接口），只多依赖 libsystemd。Yocto 构建强制编进（缺 libsystemd 就构建失败，不会悄悄只剩模拟基带）；开发机没有 libsystemd 时不编。
- **跟随**：ModemManager 起来、退出（`NameOwnerChanged`），基带出现、移除（ObjectManager）；用报上来的第一个基带。基带处于禁用状态时由 telephonyd 启用它（ModemManager 自己不启用）。基带或 ModemManager 消失时，进行中的通话以「断开」结束，状态变为未注册。
- **状态**：取自 Modem 与 Modem3gpp 的属性——本地、漫游、仅短信都算已注册；运营商名；制式按 AccessTechnologies 归成 2G–5G；信号百分比折成 0–4 格；本机号码；IMEI 取 Modem 的 `EquipmentIdentifier`。有变化就发 `status` 事件。
- **通话**：`Voice.CreateCall` 加 `Call.Start` 拨出，`Accept` 接听，`Hangup` 挂断。ModemManager 没有单路保持，保持和恢复都用 `HoldAndAccept`，对单路通话它正好就是保持和恢复；通话中接第二路来电（呼叫等待）也用它；通话中拨第二路时先 `HoldAndAccept`（没有等待、保持的通话时它只保持接通的那一路），保持了再 `CreateCall`，模拟的 ModemManager 上 `mm_test.py` 的 `outgoing_call` 测过（先 `HoldAndAccept` 后 `CreateCall`、两路时不能再拨、切换回第一路），**未上真机**。`Call.StateChanged` 换成 telephonyd 的状态；结束原因按谁挂的、接通过没有、网络给的原因，归成挂断 / 拒接 / 占线 / 未接 / 失败 / 对方挂断。结束的通话从 ModemManager 删掉。失败的通话不会停在原来的状态：`call` 事件以 `failed` 结束它，`error` 用 ModemManager 的话说为什么，telephonyd 的日志有 `call cN failed: <原因>`（Shell 和电话应用显示「通话失败：<原因>」）；包括 `CreateCall`、`Start`、`Accept` 被拒，`Accept` 30 秒没有回答，接听或拨号时 `HoldAndAccept` 被拒，网络以错误或音频建立失败结束通话。ModemManager 开始不了、接不了的通话先结束再回答，所以这种结束最多等 2 秒的回答；接了以后失败的是「失败」不是「未接」（通话记录里记成未接）。基带不肯 `Hangup` 时删掉这一路（ModemManager 删的时候挂断它）：留着的话以后每次拨号都被拒。没有基带时 `dial` 回 `ModemManager is not running` 或 `ModemManager has no modem yet`。拒绝的拨号、接听和每一路的状态写进日志，不带号码。这些在模拟的 ModemManager 上由 `mm_test.py` 测过（`answer_refused`、`answer_refused_still_ringing`、`dial_refused`、`call_audio_failed`、`hangup_refused`、`modemmanager_late`），**未上真机**。4G、5G 上打电话要 IMS（VoLTE）或回落到 2G、3G：拨出的电话没响铃就结束（不是自己挂的、不是占线、不是紧急呼叫），而基带的 IMS 没注册时，`call` 事件以 `failed` 结束，另带 `ims`（注册状态：`not-registered`、`registering`、`limited-registered`），Shell 和电话应用显示「通话失败：VoLTE 未注册」，日志有 `call cN failed on 4G with IMS (VoLTE) <状态>: <原因>`。注册状态来自板子的 SoC 配套装的程序（`--ims-status`，默认是前缀下的 `libexec/phone-telephonyd/ims-status`，没有就不判断；6T 上是 phone-qcom-ims，经 QMI 的 IMSA 服务问基带）：注册、制式、IMS 承载变了，在 4G、5G 上拨号时，还在注册时（5 秒起越来越慢，到 5 分钟）各问一次，10 秒不答就杀掉，状态变了写一行日志。最后读到的状态也放在 `status` 的 `ims` 里，读到新的就发 `status` 事件：`registered`、`registering`、`not-registered`、`limited-registered`；没装这个程序、读不到、还没读到、不在 4G 或 5G 上注册时都是 `unknown`（后端契约这样要求）。Shell 据此在状态栏画 VoLTE 标志、在「设置 › 移动网络」写出注册状态（下文 Shell 一侧）。`mm_test.py` 的 `volte_not_registered` 测过（没注册、注册了、回落到 2G、响过铃），`volte_status` 测过 `status` 的 `ims`（没装程序是 `unknown`、5G 上注册中再到注册了、2G 上和程序不见了是 `unknown`），**未上真机**（[39](39-oneplus-6t.md) §14.21）。静音属于音频通路（音频服务，R29），后端只记状态。
- **SIM 卡**：卡锁着时 ModemManager 停在 LOCKED，`UnlockRequired` 说要 PIN 还是 PUK、`UnlockRetries` 给剩余次数；`sim.unlock` 调 Sim 对象的 `SendPin` / `SendPuk`，解锁后基带回到禁用状态，telephonyd 接着启用它。卡锁着时拨号、发短信直接拒绝。开关 PIN 锁调 `EnablePin`，修改调 `ChangePin`；PIN 锁开没开读 3GPP 接口的 `EnabledFacilityLocks`（第 0 位是 SIM 卡）。
- **短信**：`Messaging.Create`（要送达回执）加 `Sms.Send` 发送，先报「发送中」，`Send` 返回后报「已发送」或「发送失败」；之后 `DeliveryState` 变了报「已送达」或「发送失败」（网络还在重试时不报），再从基带删掉，等回执的最多 64 条。收到的短信要等分段收齐（状态 RECEIVED）才算到，id 由号码、短信中心时间戳和内容算出（重启后不变）；它留在基带里，phone-smsd 确认（`sms.ack`）后才删，SIM 卡那几十条的空间不会占满，任何一边重启也丢不了；telephonyd 启动前就存在基带或 SIM 卡里的短信也这样交出去。没对上已发短信的送达报告直接删掉。时间用短信中心的时间戳。
- **小区广播**：ModemManager 1.24 的 `Modem.CellBroadcast`：设频道 4352–4359、4370–4400，收 `Added` 和 `Cbm` 对象（收齐才算到），报 `cb` 事件，smsd 确认后 `Delete`（[32](32-messaging.md) §7）；对着模拟的 ModemManager 测过（`cell_broadcast` 用例），**未上真机**。
- **USSD**：基带对象上 `Modem3gpp.Ussd` 的 `Initiate`、`Respond`、`Cancel`。`Initiate` / `Respond` 返回网络的答复后，再读一次会话的 `State`（它的 PropertiesChanged 可能晚于答复到），为 3（等用户回复）报 `input`，否则报 `done`。网络主动发来的 USSD 是 `NetworkNotification`、`NetworkRequest` 属性的变化，报 `ussd` 事件 `notify`、`input`；等回复时 `State` 回到空闲（网络结束会话），或基带、ModemManager 消失，报 `done`。基带没有 Ussd 接口、卡锁着、没注册时直接拒绝。
- **射频与移动数据**：关射频先 `Modem.Enable(false)`（ModemManager 随之结束通话和数据承载），再 `SetPowerState` 到低功耗（2）；开射频先 `SetPowerState` 到开（3），再照常启用。射频关着时 telephonyd 不再自动启用基带。射频关着拨紧急号码时先这样开，基带启用后再 `CreateCall`。移动数据开着、已注册、Service 给了接入点、漫游开关允许、没有连着的承载时，`Modem.Simple.Connect` 连上，属性是 `apn`、`ip-type`（`MMBearerIpFamily`：IPv4 1、IPv6 2、IPv4v6 4；网络默认的空接入点不给，由 ModemManager 选）、`apn-type`（上网，2）、`allow-roaming`（漫游中连的为真，telephonyd 只在开关允许时连；本地连的只在两个漫游开关都开着时为真，否则一漫游 ModemManager 自己断掉它，telephonyd 再按规则连），认证不是 `none` 时加 `allowed-auth`（`MMBearerAllowedAuth`：PAP 2、CHAP 4、两者 6）、`user`、`password`；失败了等注册状态、开关或接入点变了再试；关掉时、漫游开关不让连时、连着的承载不是要的那条时 `Simple.Disconnect` 只断那一条数据承载（给它的路径，不给 `/`：`/` 会把 IMS 承载一起断掉），断开后再按新的接入点连：telephonyd 自己连的承载（`Simple.Connect` 回的路径）按它连时用的接入点比（接入点、IP 类型、认证、用户名、密码，名字不算），别的（如 telephonyd 重启前连的）按承载 `Properties` 的 `apn`、`ip-type`、`allowed-auth`、`user` 比；承载不是要的那条时 `data_state` 是 `idle`。读到 SIM 卡（它的接入点）和已有承载的状态之前什么也不连，读到 SIM 卡之前也不因接入点不同断开已有的承载：telephonyd 重启时连着的承载留着，不会先用网络默认的接入点另连一个。SIM 卡的 SPN、GID1 取 Sim 的 `OperatorName`、`Gid1`（字节数组，写成十六进制），网络的 MNC 取 `OperatorCode`；SIM 卡换了或基带消失时忘掉接入点，等 Service 再给。`data_ip` 取连着的承载的 `Interface`、`Ip4Config`、`Ip6Config`（`method` 1 PPP、2 静态、3 DHCP，`address`、`prefix`、`gateway`、`dns1`–`dns3`、`mtu`）。`data_ifaces` 取基带的网络口（`Ports` 里类型为 net 的）和数据承载、彩信承载的 `Interface`。模拟的 ModemManager 上的用例 `mobile_data`（数据库的 `cmnet`、承载的地址；关数据只断这一条）、`apn_change`（改接入点后断开重连、`reset`；只改 IP 类型、只加认证也断开重连，只改名字不重连）、`data_roaming`（国际漫游时不连、打开数据漫游后带 `allow-roaming` 连上、国内漫游照常、关掉国内漫游后断开、再打开后连上）、`airplane_mode` 通过（`make mm-selftest`）；漫游时另用一种 IP 类型（安卓的 `roaming_protocol`）**未实现**；真网上：一加 6T 上中国移动的卡连上过（`qmapmux0.0` 有地址，[39](39-oneplus-6t.md) §16.10），改接入点、漫游、飞行模式**未上真机**。
- **别的程序开的承载**：telephonyd 只管自己连的承载（`Simple.Connect` 回的路径）和上网用的承载。别的承载按 `mm::bearer_role` 认：`BearerType` 为默认附着（2）的是 LTE 附着承载；`Properties` 里有 `apn-type` 时看它（IMS 4 或紧急 64 算 IMS，上网 2 算数据，彩信 8 算彩信，其余的不管）；没有时看 APN（ModemManager 只在请求给了时才列出 `apn-type`，81voltd 开 IMS 承载只给 APN、一个 IP 版本和配置号）：上网接入点算数据，这张卡的 IMS、紧急接入点和通用的 `ims`、`sos`（GSMA IR.92、3GPP TS 23.003）算 IMS，彩信接入点算彩信；都不是时带配置号（`profile-id`，telephonyd 从不给；81voltd 照基带请求时的给，APN 可能是空的）的不管，其余算数据（和以前一样：别的接入点上的数据承载是要换掉的那条）。只有数据承载算「移动数据已连接」、会被断开；IMS、紧急、附着承载不算数据、从不断开、网卡不进 `data_ifaces`（关移动数据时防火墙不挡它们）。用例 `ims_bearer_left_alone`：像 81voltd 那样开的 IMS 承载和标了 IMS 的承载连着时，数据承载照常连、`data_ip` 是它的，关移动数据只断数据承载，IMS 承载一直连着，再打开时在它们旁边连上数据承载，telephonyd 重启后也不碰它们。飞行模式（`Modem.Enable(false)`）照旧由 ModemManager 断掉所有承载。81voltd 还没进镜像，**未上真机**（[39](39-oneplus-6t.md) §11.1）。
- **LTE 初始附着的接入点**：接入点计划里有附着接入点（`ia`）时，telephonyd 先看 `Modem3gpp` 的 `InitialEpsBearerSettings`（基带附着时要的设置）和 `InitialEpsBearer`（网络附着上的承载）的 `Properties`：有一个已经是这个接入点（APN 不分大小写，网络在后面加的 `.mncNNN.mccNNN.gprs` 也算；给了 IP 类型、认证、用户名的要相同）就不动，否则调 `Modem3gpp.SetInitialEpsBearerSettings`（`apn`、`ip-type`，认证不是 `none` 时加 `allowed-auth`、`user`、`password`）。ModemManager 应用它时把射频关掉再打开（手机重新附着，承载都断），所以有通话（包括等射频的紧急呼叫）时不设、等通话结束，射频关着、基带没启用时也不设；设的时候数据承载等它设完再连，不会先连一次；同一个接入点只设一次（失败了也不再试，接入点计划变了才再看）。用例 `attach_apn`（启动时设一次 `cmnet`，数据承载在它之后才连）、`unacknowledged_sms_survives_a_restart`（设置已经相同，重启后不再设）、`apn_change`（改的 cmnet 也是附着接入点：先设附着再换数据承载；只改名字两样都不动）通过。真网上**未上真机**：基带记不记得住设置（记不住时 telephonyd 每次启动都再设一次，射频跟着重启一次）要在 6T 上看（[39](39-oneplus-6t.md) §14.6）。
- **SIM 卡电话簿**：ModemManager 只有存储位置的枚举，没有读电话簿的接口，后端经 `Modem.Command` 发 AT 命令（3GPP TS 27.007）：记下 `AT+CSCS?` 的字符集，切到 `UCS2`（什么文字的名字都不乱码），`AT+CPBS="SM"` 选 SIM 卡的电话簿，`AT+CPBR=?` 查记录范围，`AT+CPBR=<首>,<末>` 读出，最后把字符集改回去。号码也按 UCS2 发来的基带，解出来是号码才用；类型 145 的号码补上 `+`；空电话簿报 not found 的基带算作没有联系人。`Modem.Command` 要 ModemManager 带 `--debug` 运行才收，不然回 `the modem takes no AT commands (ModemManager needs --debug)`；镜像里还没装 ModemManager（随硬件机型的配方加上，到时要开 `--debug`），**未上真机**。高通基带也可以经 QMI 的 UIM 服务读 EF_ADN，**未实现**。
- **不被基带拖住**：所有 D-Bus 请求都异步，事件循环不会因此阻塞；等网络的请求（发短信、接听、启用、USSD）超时 120 秒；系统总线断开时 telephonyd 退出，由 systemd 重启。
- **测试**：`make mm-selftest` 在 Debian 容器里起一条私有 D-Bus 和一个 Python 写的模拟 ModemManager（`test/mock_mm.py`，导出同样的对象、属性和信号，另带一个控制接口扮演网络），通过 telephonyd 的 socket 跑 39 个用例：启用并注册、LTE 附着接入点（设一次、数据承载等它）、SIM 卡里的旧短信等确认才删、IMEI、去电、占线、来电接听 / 拒接 / 未接、保持与恢复、静音、按键音、SIM 卡电话簿（没开 `--debug` 时报错、读出、字符集改回去、空电话簿）、呼叫等待、发短信和送达回执、没有回执的短信留着等、网络拒发、分段短信只投递一次、没确认的短信 telephonyd 重启后还在（连着的承载也留着、附着接入点不再设）、小区广播、信号与制式变化、USSD 查询（一次答完、菜单与回复、网络主动发来的通知与提问、取消、网络结束会话）、SIM 卡 PIN（输错、输对）、PUK、在设置里改 PIN 和关 PIN 锁（输错、改完）、移动数据（数据库的接入点、承载的地址）、IMS 承载不算数据也不断开、改接入点（连同附着接入点）、数据漫游、彩信承载（另连一条、第二次共用、放掉、移动数据关着时没有、和上网同一接入点时走数据连接）、飞行模式、通话中基带消失又回来、ModemManager 重启、错误参数，最后是后端契约（前面所有用例里 telephonyd 报出的状态都不违反 `contract_problems`，[24](24-sku-framework.md) §8.8）。
- **紧急号码**：默认是 112、110、119、120、122、911、999，再加上 SIM 卡给的（ModemManager 的 `Sim.EmergencyNumbers`，模拟基带从 `sim-network.json` 的 `emergency_numbers` 读），`status` 的 `emergency_numbers` 告诉 Shell；SIM 卡锁着时紧急号码照样拨出（3GPP TS 22.101），别的号码拒绝；Shell 的 SIM 卡 PIN 界面上输入紧急号码按通话键就拨出，锁屏和飞行模式下也一样。单元测试和模拟的 ModemManager 上 ✓，**未上真机**；没插 SIM 卡时的真机行为要看基带，**未上真机**。
- **VoLTE（IMS）**：骁龙基带自己跑 IMS（SIP、RTP、语音编码），telephonyd 不用为它另做通话：ModemManager 经 QMI Voice 拨号时只给号码、不给呼叫类型，走 CS 还是 IMS 由基带定，`All Call Status` 报所有的通话，所以 VoLTE 通话就是普通的 `Call` 对象，拨号、接听、保持、按键音、挂断和通话的声音（q6voiced、phone-audiod）照旧（读 ModemManager 1.24.2 的源码）。基带要的 IMS 承载由 81voltd 经 ModemManager 开，基带的运营商配置由 `phone-qcom-pdc` 按 SIM 卡激活，都只在板子写了 `ims` 的镜像里（一加 6T）；telephonyd 认出 IMS 承载，不当移动数据、不断开它（[39](39-oneplus-6t.md) §11.1）。都**未上真机**（[39](39-oneplus-6t.md) §14.6）。
- **真机（一加 6T）**：整机镜像里 ModemManager 1.24.2 经 QRTR 接高通的用户态：rmtfs、tqftpserv、`phone-qcom-uim`（打开 SIM 卡的会话）和基带固件，开机时谁等谁见 [39](39-oneplus-6t.md) §14.20（R16）。实测：2026-11-25（`86fae7a`）插着中国移动的卡，移动数据连着，`qmapmux0.0` 有地址（[39](39-oneplus-6t.md) §16.10）；报告 007 的镜像上卡注册在 LTE 的本地网络，来电界面出来了，接不了，拨出也不通，日志里 q6voiced 开机时就退出了（没有它通话没有声音）。改法（q6voiced 用自己的系统用户、排在总线和 ModemManager 后面，基带这一串服务失败后一直重启，接听、拨号失败时说原因）**未上真机**（[39](39-oneplus-6t.md) §14.20）。短信、彩信、USSD、SIM 卡锁、LTE 附着接入点、VoLTE 在手机上还没有结果，**未上真机**（试法见 [39](39-oneplus-6t.md) §14.6）。
- **未实现**：VoLTE 开关、Wi-Fi 通话、视频通话（IMS 注册状态 ModemManager 1.24 没有接口，telephonyd 经板子的程序问基带，见「通话」一条）。
