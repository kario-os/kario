## 0. 结论

- **短信的存储从 telephonyd 拿出来，交给 phone-smsd。** telephonyd 只做无线一侧：发、收、送达回执、小区广播；smsd 管存下来以后的一切。这和 Android 的分层一样：RIL / 电话框架收短信、拼长短信、给网络回确认，再交给 TelephonyProvider（`mmssms.db`）存。
- **一条也不丢。** telephonyd 收到的每条短信（和每条小区广播、每条发出短信的结果）先放进自己的待确认队列（落盘），smsd 存好、同步到盘上以后用 `sms.ack` 确认，telephonyd 才放手；用 ModemManager 时，调制解调器存储里的那份也到这时才删。任何一边重启后，没确认的会再交一次，smsd 认得已经存过的（§3）。
- **不用数据库。** smsd 的存储是一个只追加的日志加一个快照：每次改动写一行、同步，攒到 256 行压成新快照；崩溃写坏的最后一行读的时候丢掉。文件 0600、目录 0700（§4）。
- **只有默认短信应用能删、能拦截。** 和 Android 只让默认短信应用写短信库一样，`sms.delete`、`sms.block`、`sms.blocked` 只给默认短信应用；它是一个角色（Android 的 `ROLE_SMS`）：默认是系统的短信，用户在设置 › 应用 › 默认应用里可以交给别的有 `sms` 权限的应用（系统先问）。别的应用有 `sms` 权限也只能读和发，而且每条都要用户确认（§8）。
- **紧急警报压在一切之上。** 小区广播按频道分级（国家级、特别严重、严重、安珀、测试），在锁屏上也弹出系统界面，用 audiod 里单独的 `alert` 类别响（静音模式也响）并振动；国家级不能关，其他级别在设置里关。带警报区域（圆、多边形）的，手机知道自己在区域外才不弹，不知道在哪就弹（§7）。
- **彩信走数据连接。** 彩信通知装在 8 位短信的 WAP 推送里；smsd 存下通知、确认短信，再经彩信接入点从彩信中心取回 m-retrieve.conf，图片交给 Shell 放进相册；发出的写成 m-send.req 交给彩信中心（§11）。
- **一份拦截名单管来电和短信。** smsd 管名单（号码、号段、隐藏号码、通讯录以外的号码）；Shell 拿一份副本，拦截号码的来电不响铃直接拒接，通话记录里记为「已拦截」（§6）。
- **号码按 E.164 比较。** 「138 0013 8000」「+86 138-0013-8000」「0086 13800138000」在中国是同一个号码，「612 34 56 78」和「+34 612345678」在西班牙也是；国外号码按当地的写法显示（§13）。

## 2. 架构

```
 网络 ──► 调制解调器 ──► telephonyd（C++，无线一侧）
                          │ 待确认队列（telephony.json 的 pending，落盘；
                          │ ModemManager：调制解调器存储里的那份）
                          │ 事件 sms / cb（带 key）     ▲ sms.ack {keys}
                          ▼                            │
                        phone-smsd（Go，存储一侧）──────┘
                          │ 日志 + 快照（state/smsd/）
                          │ 事件 message / changed / alert；unnotified + notified
                          ▼
                        Shell：通知（复制验证码）、闪信对话框、紧急警报界面、
                          │    彩信图片进相册、拦截来电、broker（sms.*、block.*）
                          │
                          ▼
                        短信应用（默认短信应用）、其他有 sms 权限的应用
```

smsd 是 telephonyd 的第二个客户端（另一个是 Shell）；应用只经 broker 到 smsd。彩信不经 telephonyd：smsd 直接经彩信接入点用 HTTP 和彩信中心说话（§11）。

## 3. 交接：一条短信不丢

1. telephonyd 收到短信，生成事件 `{"event":"sms","key":…,"sms":{…}}` 放进待确认队列，写盘（先写临时文件、`fsync`、再改名），再广播。用 ModemManager 时 id 从号码、短信中心时间戳和内容算出来（FNV-1a），ModemManager 重启后给的同一条短信 id 不变，队列里也只放一次。
2. smsd 订阅 telephonyd，每次连上先要 `sms.pending`：smsd 不在时收到的、上次没来得及确认的都在里面。
3. smsd 存好（日志同步到盘）以后才发 `sms.ack`。存过的 id 记在最近 2000 条的名单里，再交来的只确认不再存。
4. telephonyd 收到确认才把它从队列删掉；用 ModemManager 时这时才调 `Messaging.Delete` 删调制解调器存储里的那份（SIM 卡上只有几十个位置，满了就收不了新短信）。
5. 发出短信的结果（`sent`、`delivered`、`failed`）和小区广播走同样的确认；`sending` 是 smsd 自己记的，不进队列。
6. telephonyd 以前自己存的短信（`telephony.json` 里的 `sms`）由 smsd 每次连上时用 `sms.legacy` 取走、存好，再用 `sms.legacy_drop` 让 telephonyd 删掉；做到一半崩溃也没关系，再来一次时按 id 跳过已有的。

| 谁重启 | 结果 |
|--------|------|
| smsd 崩溃，短信这时到 | 留在 telephonyd 的队列里；smsd 起来后从 `sms.pending` 拿到、存、确认（自测 §10） |
| smsd 存好、还没确认就崩溃 | telephonyd 再交一次；smsd 认得 id，只确认 |
| telephonyd 重启（模拟基带） | 队列从 `telephony.json` 读回来；smsd 重连时从 `sms.pending` 拿到（自测 §10：测试钩子 `sim.sms` 带 `held` 时只入队、不发事件，像 telephonyd 存下后就崩溃，再杀掉 telephonyd） |
| telephonyd 重启（ModemManager） | 没确认的还在调制解调器存储里，重新列出来，id 不变 |
| Shell 不在（或重连前） | smsd 照样存；没显示过的新短信和警报留在 smsd 的「未通知」名单里，Shell 一订阅就用 `unnotified` 取走，显示后用 `notified` 确认 |
| smsd 重启时短信应用正在读会话（或开机时比 smsd 先起来） | 那次调用失败；系统的短信不把它当成没有短信：留着上次读到的列表和会话，什么都没读到时写「短信暂时读不出来，稍后会自己显示。」（§9）；Shell 一订阅到 smsd 就给在跑的默认短信应用和系统的「短信」发 `sms` 事件，它们重新读（`TestSMSAppsHearSmsdBack`；自测 §10） |

## 4. 存储

- 目录 `<state>/smsd/`（0700）：`snapshot.json`（0600）和 `log`（0600，一行一个改动，带序号）。读的时候先读快照，再按序号重放日志里更新的行；最后一行没写完就截掉。
- 压缩：日志攒到 256 行就写新快照（临时文件、`fsync`、改名、同步目录），再清空日志；两步之间崩溃，重放时按序号跳过快照里已有的。
- 上限：短信 10000 条（多了丢最早的）、警报 500 条、记住的已收 id 2000 个、未通知 200 个、等送达报告的彩信 256 条、草稿 500 个。
- 草稿：每个会话一份（`sms.draft {peer, text}`，只给默认短信应用；`text` 为空就删掉，至多 5000 字），作一个改动存下；`sms.threads` 带出 `draft` 和 `draft_at`，只有草稿的会话也列出来（条数 0），按 `draft_at` 和最后一条中较晚的排；往这个会话发短信（新的或定时的）的那个改动同时删掉草稿。按会话的键找，换了地区照样找得到。
- 彩信的附件：`<state>/smsd/parts/<短信 id>.<序号>`（0600），先写文件再记改动；Shell 把图片放进相册后 smsd 删掉自己那份（`part.media`）。发出的彩信 PDU 留在 `outbox/` 里，彩信中心收下才删（重发用它）。启动时清掉没有短信用的文件。
- 会话按规整后的号码分（§13）：能认出国家的号码按 E.164（`+8613800138000`），短号码（10086、95588）按写出来的数字，带字母的发送方（公司名）不分大小写；群聊的会话是所有成员号码排序后用逗号连起来。按哪个地区读国内写法的号码由 Shell 告诉 smsd（`region`），换了地区所有会话重新规整；以前存的（中国号码不带 `+86`）读的时候也重新规整。
- 搜索在内存里做：内容（不分大小写）、号码；联系人的名字由短信应用自己匹配（smsd 不认识通讯录）。
- 导入（从旧手机迁移，[36](36-device-switch.md) §7；经蓝牙从旧手机的 MAP 读来的短信也走它，§8）：只有 Shell 调的 `import` 收 `{messages: [{peer, dir, text, at, read}]}`（一次至多 500 条，`at` 是 Unix 秒），作一个改动存下：每条按时间排进去（插在第一条比它晚的前面，原有的顺序不变），收到的已读未读照给的，发出的记成已读、`sent`，都标 `imported`；收到的照常认验证码，拦截号码的进「已拦截」；不进未通知名单，不发通知，只发一次 `changed`。没有号码、没有内容、方向不是 `in` / `out`、`at` 不大于 0 的，和已有的（同一会话、方向、时间、内容）不存。恢复备份（§4.1）也走它：彩信（`kind: "mms"`）带主题、文字（至多 5000 字）和群聊成员，发出的 `state: "failed"` 照旧记成没发出。返回 `{ids}`，按位置是每条的新 id（`i` 开头），没存的为空。`delete_imported` 的 `{ids}` 只删其中导入的（撤销这次导入），返回 `{deleted}`。

### 4.1 备份和恢复（安卓「SMS Backup & Restore」的 XML）

从安卓换过来的人手里多半有这个应用（SyncTech）做的备份：根元素 `<smses>`，每条短信一个 `<sms>`，每条彩信一个 `<mms>`（下面 `<parts>` 里的 `<part>` 和 `<addrs>` 里的 `<addr>`），内容都在属性里。Kario 读写的就是这个格式（`smsbackup` 包），文件放在「文件」里，用户自己决定拷到哪里。

- 备份（`sms.backup`，只给默认短信应用）：Shell 向 smsd 要全部短信（含「已拦截」），按时间写，定时的和正在发的不写。短信写 `address`、`date`（毫秒）、`type`（1 收到、2 发出、5 没发出）、`body`、`read`、`readable_date`、`contact_name`；彩信写 `msg_box`、`m_type`（132 收到、128 发出）、`address`（号码用 `~` 连起来）、`sub`、一个 `text/plain` 的 `part`、`addr`（137 发送人、151 收件人；不知道本机号码时写安卓的 `insert-address-token`）。图片不写进备份（它们在相册里）。换行写成 `&#10;`。系统先写明条数和文件名（`sms-年月日时分秒.xml`，安卓那个应用也认这个名字），确认后存进「文件」；文件不交给应用。
- 恢复（`sms.restore`，只给默认短信应用）：系统列出「文件」里的 `.xml`，用户选一个；Shell 在主循环外读（文件可能很大），写明有几条，确认后每 500 条一批交给 smsd 的 `import`（§4）：已有的（同一会话、方向、时间、内容）跳过，所以恢复自己的备份一条也不多；不通知，收到的照常认验证码、按拦截名单分。读的是收到、发出、没发出的短信，收到和发出的彩信的主题、文字部分和群聊成员（收件人里去掉本机号码）；草稿、发件箱里的、只有图片的彩信、日期在 2000 年以前的不算，计进 `skipped`。smsd 至多存 10000 条，更多的恢复进去时最早的照常丢掉。
- 读法：备份文件是不可信输入，用的是自己写的小扫描器，不用 `encoding/xml`：彩信图片的 base64（`data`，可能几 MB）边读边丢，不进内存；那个应用把表情写成两个数字引用（UTF-16 的代理对，如 `&#55357;&#56832;`），读时合成一个字；控制字符丢掉而不是报错。属性值至多留 20000 字节（多的读过不留），文字至多 5000 字、主题 200 字、号码 64 字节，至多 20000 条、合计 32 MB 文字；文件截断时保留已经读到的。有模糊测试（`smsbackup`：`FuzzParse`，[17](17-app-sandbox.md) §9）。

## 5. 发送和送达回执

- `sms.send` 先存成 `sending`，再交给 telephonyd（带 smsd 的 id，之后的事件用同一个 id）；telephonyd 不在就直接记成 `failed`。
- 送达回执：模拟网络发出 0.5 秒后报 `delivered`（号码以 999 结尾的发不出去，以 998 结尾的发出去但永远收不到回执）；ModemManager 创建短信时要回执（`delivery-report-request`），收到 `DeliveryState` 后按类别报 `delivered` 或 `failed`，网络还在重试时不报；等回执的短信最多留 64 条，多了最早的放弃。
- 状态只往前走（`sending` < `sent` < `delivered` / `failed`），晚到的、重复的回执不会把它退回去；重发（只有默认短信应用，`sms.send {id}`）从 `failed` 回到 `sending`。
- 发了 3 分钟还是 `sending`（telephonyd 中途退出，ModemManager 2 分钟就放弃），smsd 记成 `failed`。
- 分条计数（短信应用和 smsd 共用 `ui.SMSSegments`）：GSM 7 位字母表 160 字一条、拆开后每条 153；有字母表以外的字（中文、表情）用 UCS-2，70 / 67；smsd 不发超过 10 条的。
- 带图片、带主题或发给几个人（逗号或分号隔开，至多 20 个）的作为彩信发（§11）；Android 的群发默认也是彩信。

### 5.1 定时发送

- `sms.send` 带 `at`（Unix 秒）就是定时，只给默认短信应用；时间已过（超过 1 分钟）或在一年以后的不收。smsd 把它存成发出的短信，`state: "scheduled"`，`due` 是发出的时刻，`zone` 是选时间时手机的时区（只用来显示）；彩信也一样（PDU 先写进 `outbox/`）。它在日志和快照里，smsd 重启后还在。
- 到点：smsd 的定时器在下一条到期时醒来，至少每 30 秒也醒一次，按墙上的时钟比（手动调了时间也按新时间发）；到期的照重发的路子发出（`sending` → `sent` …），时间改成发出的时刻，排到会话最后。关机或 smsd 没在运行时过了时间的，smsd 一起来就发。
- 时区：定的是那一刻，不是钟面上的几点。短信应用把用户在手机当前时区选的日期和时间换成 Unix 秒；之后手机换了时区，还是在那一刻发。会话里按现在的时区显示，时区和选时间时不同时，再写上原来时区的钟点（「定时发送 · 2026-11-19 20:00 (09:00 Asia/Shanghai)」）；页面上写明这一点。夏令时跳过的钟点按 Go 的 `time.Date` 规整。
- 取消就是删掉（`sms.delete`）；会话里对着定时短信有「立即发送」（`sms.send {id}`）和「取消发送」。自测用 `schedule.sim` 让 smsd 马上发出定时的（只在模拟基带上收）。`scheduled` 只读，回答现在还等着的定时短信有几条（`{scheduled}`）：自测在每个用例开头和结尾各问一次，用例留下的定时短信让它失败（[40](40-testing.md) §2）；旧的 smsd 不认识它，就不查。

## 6. 拦截和验证码

- 一份拦截名单管来电和短信（Android 的 BlockedNumberProvider），smsd 存：号码按 E.164 规整后记（§13）；号段以 `*` 结尾（`1065*`：所有以 1065 开头的号码），和号码的 E.164、国内号码（带不带长途冠码 0）、写出来的数字比前缀；两个开关：拦截隐藏号码（来电不显示号码：空，或网络给的 unknown、private、anonymous 一类的词），拦截通讯录以外的号码（短号码和带名字的发送方也算；Shell 把通讯录里的号码交给 smsd，没交之前这个开关不拦短信）。紧急号码的来电不拦。
- 关键词（`block.set {word, on}`，名单里的 `words`）只管短信：收到的短信、彩信通知的主题、下载下来的彩信文字、闪信、导入和恢复的收到的短信，正文或主题里含有其中一个词就进「已拦截」，不管谁发的（彩信下载后才看出来的也移过去，不通知）。比较时两边都只留字母和数字、转成小写、全角转半角（`ui.WordKey`），字中间夹了空格或符号（「代 开*发 票」）也拦得住；只有符号的词不收。至多 200 个，每个至多 40 字；比较时一样的算一个。设置 › 号码拦截和短信的「已拦截」页都能加、删。
- 拦截号码的短信直接进「已拦截」文件夹，标为已读，不发通知、不进未通知名单；彩信通知也进「已拦截」，不自动下载（用户在「已拦截」里按「下载」才取）。取消拦截以后的短信照常；以前的还在「已拦截」里。
- 来电：Shell 拿着名单的副本（smsd 一说名单变了就重取），来电一到先查，拦截的不响铃、不弹来电界面、不发未接来电通知，直接挂断（`hangup` 带 `blocked`），telephonyd 在通话记录里记成 `blocked`，电话应用显示「已拦截」。
- 谁能改：默认短信应用、系统的电话、设置（`block.list`、`block.set`）；旧的 `sms.block`、`sms.blocked` 照旧给默认短信应用。界面：短信应用的「已拦截」页、会话菜单「拦截此号码」；电话的通话记录菜单「拦截此号码」/「取消拦截此号码」；设置 › 隐私与安全 › 号码拦截（号码、号段、两个开关）。
- 验证码：4–8 位数字（或用一个空格 / 横线隔开的两段，如 `123 456`），附近要有说明验证码的词，取离词最近的一个，最多隔 40 个字。金额（前面是货币符号、后面是「元」或小数）、年份、时间（冒号）、数量单位、超过 8 位的号码不算。这些词和符号是中文、英文、西班牙文的数据，放在 `programs/smsd/otp.json`，不写在代码里。
- 识别出的验证码随短信存（`code`）：通知上有「复制验证码」（Shell 自己复制，短信应用不用启动），会话里对着那条短信按 `c` 也能复制；剪贴板照旧只能由用户在输入框里粘贴。应用要验证码时用 `sms.otp`（§6.1）。

### 6.1 把验证码交给应用（`sms.otp`）

登录时应用不用读短信：先调 `sms.otp {seconds?}`（默认 120 秒，至多 300）开始等，再让自己的服务器发验证码。下一条带验证码的短信（smsd 识别出的 `code`；发起以后到的才算，进「已拦截」的不算）到了，Shell 弹系统对话框：「「应用」要这条短信里的验证码：发送人：内容；把验证码 123456 交给它？」，用户按「交给它」，应用拿到 `{code, from}`，别的短信什么都拿不到；按取消回 `cancelled`，等不到回错误。同一个应用再发起就取代上一次（上一次回 `cancelled`）；几个应用同时在等时先给前台的，否则给等得最久的。锁屏设了 PIN 码时不弹（验证码不显示在锁着的屏幕上），接着等。应用退出后那次等待作废。像安卓的 SMS User Consent API：不要权限，用户的同意就是授权。示例：`examples/smslite` 的「等验证码」。

## 7. 紧急警报（小区广播）

| 频道（3GPP TS 23.041） | 级别 | 能关吗 |
|------------------------|------|--------|
| 4370、4383 | 国家级（`presidential`） | 不能 |
| 4371–4372、4384–4385；ETWS 4352–4354、4356 | 特别严重（`extreme`） | 能，默认开 |
| 4373–4378、4386–4391、4396–4397 | 严重（`severe`） | 能，默认开 |
| 4379、4392 | 安珀（`amber`） | 能，默认开 |
| 其他（每月测试、演习、运营商、ETWS 测试等） | 测试（`test`） | 能，默认关 |

- telephonyd：模拟网络用测试钩子 `sim.cb {channel, serial, text}` 发一条；ModemManager 1.24（Yocto 层里 meta-openembedded wrynose 的 `modemmanager_1.24.2`）有 `org.freedesktop.ModemManager1.Modem.CellBroadcast`：telephonyd 设频道 4352–4359、4370–4400（`SetChannels`），收 `Added` 和 `Cbm` 对象（`State`、`Text`、`Channel`、`MessageCode`、`Update`），smsd 确认后 `Delete`。ModemManager 一侧对着模拟的 ModemManager 测过（`cell_broadcast` 用例），**未上真机**；调制解调器的小区广播支持因型号而异。
- smsd 去重：同一频道、同一序列号（消息码 + 更新号）24 小时内只算一条；序列号变了（警报更新）算新的。全部警报都存，不管级别开没开。
- Shell：级别开着就弹系统界面 `alertOverlay`：锁屏上也压在最上面（锁屏关对话框时它留着），挂断键不关它，按 OK 或返回才关；屏幕亮起；audiod 新类别 `alert`（优先级最高、音量 1、静音模式也响）播 853 Hz + 960 Hz 的提示音（2 秒、半秒、半秒，循环到关掉）；振动三下。级别关着就只记录。
- 设置 › 紧急警报：每个级别一行，国家级写着「总是显示」；`settings.set` 的键 `alert_extreme`、`alert_severe`、`alert_amber`、`alert_test`。
- 短信应用 › 紧急警报：收到过的警报（级别、内容、时间、频道）。

### 7.1 警报区域（地理围栏）

WEA 3.0（ATIS-0700041）的警报可以带警报区域坐标（WAC）：圆（中心和半径）或多边形，还可以带「最多等多久定位」。telephonyd 把 WAC 原样（十六进制）交给 smsd（模拟网络：`sim.cb` 的 `wac`；ModemManager 1.24 的 `Cbm` 对象不给 WAC，**未实现**）。smsd 按 Android 的读法解析（两字节小端长度，然后一个个形状：4 位类型、10 位长度、2 位空；坐标 22 位纬度、22 位经度，半径 20 位、单位 1/64 千米；`ui.ParseWAC`），解析不了就当没有区域；警报照样全存。

规则（Shell 的 `alertWhere`）：

| 情况 | 弹不弹 |
|------|--------|
| 警报没有区域 | 弹（按级别开关） |
| 有区域，最近一次定位不超过 30 分钟，位置（考虑精度：离区域边界不超过精度半径都算在内）在某个形状里 | 弹 |
| 有区域，最近一次定位不超过 30 分钟，在所有形状外 | 不弹，只记录（日志、`AlertsOutside`） |
| 有区域，没定位过、定位超过 30 分钟、或位置开关关着 | 弹（宁可在区域外也弹，不能在区域内漏掉） |

Shell 不为警报专门打开定位接收机，只用应用最近一次定位留下的位置；「最多等多久定位」读出来但不用，**未实现**。

## 8. 能力和默认短信应用

| 能力 | 谁能用 |
|------|--------|
| `sms.send` | `sms` 权限；不是默认短信应用的商店应用每条都由系统写明发给谁、发什么（带几张图片），用户确认才发；只有默认短信应用能 `{id}` 重发、能带 `at` 定时；`media` 只能是应用看得到的照片 |
| `sms.list`、`sms.read`、`sms.threads`、`sms.alerts` | `sms` 权限 |
| `sms.delete`、`sms.block`、`sms.blocked`、`sms.download`、`sms.draft`、`sms.backup`、`sms.restore` | `sms` 权限，而且只给默认短信应用 |
| `sms.vcard` | `sms` 权限；联系人由系统确认后才加 |
| `sms.otp` | 不要权限；用户同意才交出验证码 |
| `block.list`、`block.set` | 默认短信应用、系统的电话、设置 |

默认短信应用是 `sms` 角色（`smsrole.go`）：设置 › 应用 › 默认应用列出系统的短信和其他声明了 `sms` 权限的应用；选商店装的应用时系统先问（「它不用询问就能读、发、删短信和拦截号码」），选系统的短信不问；`settings.set` 的键 `sms_app`（文字是应用 ID）。拿着角色的应用：删短信、管拦截名单、发短信不逐条确认、收到的新短信由它发通知、收到的彩信图片它看得到（`media.grant`）；系统的短信这时只能读和发（删除会被拒）。拿着角色的应用被卸载，角色回到系统的短信；以后再装同一个 ID 的应用，要重新选、重新确认。示例：`examples/smslite`（商店装的最简短信应用，自测用它）。

参数和结果见 [22](22-developer-api.md) §4.2；没有 `sms` 权限的应用调这些都被拒（兼容测试探针逐个检查）。

## 9. 短信应用

- 会话列表：联系人名字或号码（群聊是所有成员）、最后一条（发出的写「我：」，没发出去的写「未发出：」，彩信写主题和文字，只有图片的写「图片」）、时间、未读数；有草稿的写「草稿：」，最后一条是定时的写「定时：」；每个会话的菜单里有「删除会话」（先确认，连草稿一起删）、「拦截此号码」（先确认）。右软键写新信息；页面菜单：搜索（`s`）、已拦截（`k`）、紧急警报（`e`）、备份到文件（`f`）、从文件恢复（`r`）。
- 会话：两边的气泡，发出的写「发送中…」「已发出」「已送达」「未发出」；彩信的图片接在气泡下面（图片节点 `media:<id>`），相册不收的附件写名字、类型和大小；没下载下来的写「彩信，正在下载…」/「未下载」（可「下载」）/「已在运营商处过期」；群聊里收到的写发送人；保存的闪信标「闪信」；彩信里的名片写「名片：名字」，按 OK「加入通讯录」；定时短信排在最后，写「定时发送 · 时间」。对着一条短信：重发（没发出去时）、立即发送和取消发送（`x`，定时的）、复制验证码（`c`）、复制内容（`y`）、删除（`d`，先确认）；页面菜单：添加图片（`p`，系统的照片选择器，至多 5 张）、定时发送（`t`）、打电话、删除会话、拦截 / 取消拦截，号码不在通讯录里时还有「保存号码」。输入框里是这个会话的草稿；离开会话、应用转到后台时，没发的内容存成草稿。输入框下面是分条计数（「还可输入 68 字 · 1 条」），带了图片或是群聊就写「彩信」。通讯录的「发短信」经 `message.compose` 打开和那个号码的会话，离开会话时回到通讯录。
- 新信息：收件人（几个号码用逗号隔开就是群发彩信）、内容、分条计数、发送；分享来的文字已经填好；页面菜单：选择联系人（`c`，系统的联系人选择器，选中的号码加进收件人）、定时发送（`t`）。没发就离开时，收件人和内容都有就存成那个会话的草稿。
- 定时发送：日期、时间（系统的日期和时间框，默认一小时后）、写明按哪个时区的钟点、到时换了时区也在这一刻发；右软键「定时」。
- 搜索：边打边搜内容（含彩信主题）、号码和联系人名字。
- 已拦截：拦截的号码和号段（OK 取消拦截）、拦截号码发来的会话、两个开关现在的状态；页面菜单：「拦截号码」（`a`，号码或以 `*` 结尾的号段）、「拦截关键词」（`w`）、「拦截隐藏号码」（`h`）、「拦截通讯录以外的号码」（`u`）（和设置里的是同一份名单）；拦截的关键词列在号码下面，OK 取消。
- 紧急警报：记录和每条的详情。
- smsd 不应答时（它重启时、开机比它先起来时）读不到的不当成没有：会话列表和打开的会话留着上次读到的，什么都没读到时写「短信暂时读不出来，稍后会自己显示。」，不写「没有短信」；搜索、已拦截、紧急警报也写这一句，不写「找到 0 条」「没有」。smsd 回来后 Shell 发 `sms` 事件（§3），打开着的这些页面重新读；不轮询。

## 11. 彩信

> **MVP，未上真机**：收发都对着假彩信中心（`mms.FakeMMSC`，单元测试、自测和模拟基带）跑通；真运营商的彩信中心、彩信接入点和数据承载没试过。

```
运营商 ──WAP 推送（8 位短信，端口 2948）──► telephonyd ──sms {data}──► smsd
                                                              │ 存「彩信通知」（待下载），确认短信
                                                              │ GET content-location ──► 彩信中心（经彩信代理）
                                                              │ ◄── m-retrieve.conf
                                                              │ 存文字和附件，通知 Shell；POST m-notifyresp.ind
                                                              ▼
                                         Shell：图片放进相册（part / part.media），通知，会话
发：短信应用 sms.send {media} ─► Shell 读照片 ─► smsd：缩图、m-send.req ──POST──► 彩信中心 ◄── m-send.conf
送达报告：彩信中心 ──WAP 推送 m-delivery.ind──► smsd 按 Message-ID 记「已送达」
```

- **收**：telephonyd 把 8 位短信的用户数据原样（十六进制）交出来（模拟网络：`sim.sms` 的 `data`；ModemManager：SMS 的 `Data` 属性，**未验证**）。smsd 读 WSP 推送（前面还带着 UDH 的也认），内容类型是 `application/vnd.wap.mms-message`（或应用 ID 是彩信用户代理）的读 MMS PDU：m-notification.ind 存成一条待下载的彩信（发送人是通知里的 From，不是推送短信的运营商网关号码），存好就确认短信；m-delivery.ind 是送达报告。`application/vnd.wap.sic`（服务指示）存成一条普通短信：说明文字和链接，系统不会自己打开链接。别的数据短信丢掉（没有应用监听数据端口）。
- **下载**：后台按到期时间逐个取（`mmsLoop`，有新通知立即取，否则每 30 秒看一次）；`GET` 通知里的地址，最多 2 MB，不跟随重定向，2 分钟超时；成功后按 SMIL 的顺序拆开：文字部分合成正文（字符集：UTF-8、GBK、GB18030、Big5、UCS-2 / UTF-16 等），其他部分存成附件文件；再 `POST` m-notifyresp.ind（Retrieved）告诉彩信中心。失败等 30 秒、2 分钟、10 分钟再试，第四次还失败标「未下载」并通知，短信应用里按「下载」再取（`sms.download`）；过了通知里的有效期标「已过期」。
- **谁能让手机去取**：通知谁都能发（伪造的 WAP 推送）。经运营商的彩信代理取时，能到哪里由运营商的网络决定；没有代理时（只有自测的假彩信中心）只取彩信中心那台主机上的地址，不让一条短信叫手机去连任意网址。
- **附件和相册**：附件先存在 smsd（§4）；Shell 收到「已下载」的事件后，把 PNG、JPEG、GIF（取第一帧转成 PNG）放进相册（名字「某某的彩信」），告诉 smsd 换成 `media:<id>`，smsd 删掉自己那份；相册不收的（音频、视频、vCard）留在 smsd，短信应用写名字、类型和大小；vCard（`text/vcard`、`text/x-vcard` 或 `.vcf`）写「名片：名字」，按「加入通讯录」由系统读出联系人、写明有几个新的、确认后加入（`sms.vcard`，和从「文件」导入名片同一条路）。删短信不删相册里的图片。拦截文件夹里的彩信不进相册。
- **群聊**：收到的彩信的 To、Cc 加上发送人，去掉本机号码（telephonyd 状态里的 `own`；不知道本机号码时，只有一个收件人就当是本机），剩下不止一个就是群聊：`members` 是这些号码，会话是它们规整后排序连起来；在群聊里回复就发给所有人。发出的：收件人不止一个就是群聊。
- **发**：Shell 把应用给的照片（只能是应用看得到的，`media:<id>`）读出来交给 smsd；smsd 把每张图缩到合适（最长边 1280，JPEG 质量一档档降，整条不超过 300 KB），写 m-send.req（SMIL、图片、UTF-8 文字，multipart/related，要送达报告），先存进 `outbox/`，再 `POST` 给彩信中心；m-send.conf 是 OK 就记「已发出」并记下 Message-ID（最近 256 个），不是就「未发出」，重发用存着的 PDU。
- **彩信接入点**（`apn.go`）：先问 telephonyd 的 `apn.mms`：它的 APN 数据库（连同用户的改动）给这张 SIM 卡的 mms 类 APN，照数据库写 APN 的样子返回（smsd 只读 `apn`、`mmsc`、`mms_proxy`、`mms_port`，`svc.MMSAPN`）；问不到或没有 `mmsc` 就按 SIM 卡的运营商用公开的设置：中国移动 `http://mmsc.monternet.com`、代理 `10.0.0.172:80`（cmwap）；中国联通 `http://mmsc.myuni.com.cn`、`10.0.0.172:80`（3gwap）；中国电信 `http://mmsc.vnet.mobi`、`10.0.0.200:80`（ctwap）——按 MCC 460 加 MNC（telephonyd 状态里有 `sim_mnc` 时），没有 MNC 就按运营商名字。模拟基带上不管模拟 SIM 卡的 APN 怎么写：自测给了假彩信中心就用它（`mms.sim`，只在 telephonyd 是模拟基带时接受），否则 smsd 在自己进程的回环端口上起一个（`mms.FakeMMSC`），收下发出的彩信，0.5 秒后像模拟网络对短信那样经 telephonyd 的 `sim.sms` 给每个收件人发一个送达报告的 WAP 推送（号码 `1065800000`）。运营商把彩信放在单独的接入点上时（中国移动的 cmwap 和上网的 cmnet），彩信要走第二个 PDP 上下文：smsd 每次取回、发出、回 m-notifyresp.ind 之前问 telephonyd 的 `mms.connect`，telephonyd 在彩信接入点上另连一条承载（从每次调用起保持三分钟），回它的网卡和地址；Shell 给这块网卡配上地址和一张只管它的路由表，策略规则只把从这个地址出去的包交给这张表（[04](04-ui-language-telephonyd.md) Shell 一侧）；smsd 等网卡上有了这个地址（最多 10 秒），连接和 DNS 查询（问承载给的 DNS 服务器）都从这个地址出去，所以经彩信承载到代理，手机别的流量不受影响；同时进行的几次收发共用一条，最后一次结束时 `mms.disconnect` 放掉。彩信接入点和上网的是同一个时 telephonyd 回 `shared`，smsd 照旧经手机现有的路由去连代理；模拟基带、自测的假彩信中心、没有这个方法的 telephonyd、telephonyd 不在时也一样。移动数据关着、漫游开关不让连、承载连不上时这次收发失败，照下载的重试再来。单元测试（假 telephonyd、从 127.0.0.2 发出去的连接）和模拟的 ModemManager 上的承载 ✓，**未上真机**：真网上第二条承载连不连得上（ModemManager 在高通 QRTR 上开多路承载）、彩信中心收不收从它来的请求都要在 6T 上看（[39](39-oneplus-6t.md) §14.6）。
- 解析的都是不可信输入：WSP 推送、MMS PDU（头、多部分，至多 64 个部分、64 个收件人、256 个头）、SMIL（至多 64 KB）、服务指示（WBXML），都有模糊测试（[17](17-app-sandbox.md) §9）。

## 12. 闪信（class 0）

- telephonyd 报短信的消息类别（模拟网络：`sim.sms` 的 `class`；ModemManager：SMS 的 `Class` 属性，**未验证**）。
- class 0 的短信 smsd 不存，放在内存里（至多 20 条）交给 Shell（`flash` 事件；Shell 没订阅时在 `unnotified` 的 `flash` 里）；Shell 弹系统对话框（锁屏上也弹，锁屏不关它，亮屏、振动一下），标题「某某发来的闪信」，OK 保存、返回关闭。Shell 显示过（`notified`）以后 smsd 才让 telephonyd 放手：Shell 不在、smsd 崩溃时到的闪信不会丢，会再显示一次。
- 保存（`flash.save`）：作为已读的短信存进收件箱，标 `flash`，短信应用里写「闪信」。关掉就没有了。
- 拦截号码的 class 0 短信和普通短信一样进「已拦截」。

## 13. 号码规整（E.164）

- `phonenum` 包：精简的 libphonenumber 式元数据（`phonenum/metadata.json`，我们自己按 ITU-T E.164、E.212 和各国编号计划写的）：每个地区的国家码、移动国家码（MCC）、国际冠码（00、011、0011、810 …）、国内（长途）冠码（0、1、8、墨西哥的 01 / 044 / 045 …）、国内有效号码的长度、几种显示格式。覆盖语言设置里的地区（中国大陆、港澳台、21 个西班牙语国家和地区）和美国、加拿大、英国、爱尔兰、欧洲主要国家、俄罗斯、哈萨克斯坦、土耳其、日本、韩国、东南亚、印度、澳新、海湾、南非、埃及、尼日利亚，共 62 个；表外国家的号码只认国家码（ITU 的国家码不重前缀）。
- 读号码：带 `+` 或本地区的国际冠码的按国家码读；国内写法按地区读，去掉国内冠码（中国的 `010 1234 5678` → `+861012345678`），号码长度是那个国家用的才算有效；国家码后面误写了国内冠码的（`+44 (0)20 …`、`+44 020 …`）去掉；墨西哥旧的手机 `1`、阿根廷手机国内写的 `15`（变成国际写法的 `9`）按规则换掉。
- 比较（`phonenum.Key`、`ui.NumberKey`）：有效的号码比 E.164；本国的短号码（10086、911）比数字，所以 `10086` 和 `+8610086` 是一个；别国的无效号码保留国家码；带字母的发送方不分大小写。会话、通讯录（Shell 的索引）、拦截名单都用它。
- 地区：Shell 的地区（设置 › 地区，默认跟 SIM 卡的国家，[11](11-platform-architecture.md)）；Shell 把它设成本进程的默认，告诉 smsd（`region`），应用进程从环境变量 `PHONE_REGION` 得到。换了地区，通讯录的索引和 smsd 的会话、拦截名单重新规整。
- 显示（`phonenum.Display`、`ui.NumberText`）：带国家码写的号码（网络发来的发送方常这样）按地区的习惯显示：本国号码用国内写法（`+8613800138000` → `138 0013 8000`，`+12015550123` 在美国 → `(201) 555-0123`），外国号码在国家码后分组（`+34 612 34 56 78`）；国内写法写的、短号码、名字原样显示。
