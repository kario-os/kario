# 按键交互语法与语义 UI 模型

> 回答「B站、微信那种到处是入口、长按还有菜单的界面，按键能不能做」。
> 状态：设计草案；§3 的规则和 §4 的 `phone.Ui` v0 已在原型实现（[13](13-prototype.md)）；有触摸屏的整机上触摸是第二种输入，换成按键（§2.1，2026-11-25 实现，**未上真机**）。**未实现**的：§2 里的多选（「标记」）、文本选择模式、底部 Tab 栏和 `Alt+←/→` 切页；§4.4 的紧凑（二进制）序列化，现在是 fd 3 上的 JSON 行，增量只到整页。为什么这样选见 [09](09-ui-feasibility-review.md)；IPC 见 [03](03-protocols-and-ui-path.md)；输入法见 [16](16-input-method.md)。

## 1. 物理键位（目标机身：QWERTY 直板）

| 键 | 作用 |
|----|------|
| 方向键 / 触控板 | 移动焦点；网格里二维移动 |
| OK（中键） | 焦点元素的**主动作** |
| 菜单键（或长按 OK） | 焦点元素的**上下文菜单**（= 触屏长按） |
| 左软键「选项」 | 页面菜单：焦点动作 + 本页动作 + 全局动作 |
| 右软键 | 本页的创建 / 主操作（发评论、写短信），标签随页面变 |
| 返回 | 退一层，保留状态（列表位置、草稿） |
| 通话 / 挂断 | 全局：拨号、接听；挂断兼作「回待机」；没有单独电源键的机型挂断键也是电源键（诺基亚的做法）：按住打开电源菜单，在待机界面或锁屏上连按两下打开快速选卡（[18](18-nokia-form-factors.md) §5.1）；电源菜单或快速选卡开着时按一下只关掉它，不回待机；闹钟响着时按一下是稍后提醒（和电源键一样），从不停止闹钟（有单独电源键的机型挂断键不动闹钟）。每种机型怎么关机见 [18](18-nokia-form-factors.md) §5.1 的「怎么关机」 |
| 电源键（`power`，板子有单独的电源键时） | 按一下息屏或亮屏；闹钟响着时按一下是稍后提醒（5 分钟后再响，像安卓），来电响铃时是静音；连按两下打开快速选卡（任何界面，锁着也行，[30](30-nfc.md) §5；连按三下以上只是息屏、亮屏）；按住长按的时间（默认 600 ms，不短于 500 ms）打开电源菜单（取消、关机、重启、飞行模式，打开时选着「取消」）。电源菜单或快速选卡开着时按一下只关掉它、屏幕不熄；只有电源键和音量键（没接能按 OK 的键盘，如一加 6T）时音量键移动电源菜单的选中项，按一下电源键选中它；屏幕熄灭时两个菜单都关掉，[28](28-battery.md) §7（**未上真机**） |
| 全键盘字母 | 不在输入框时：快捷键，或打字即搜索（待机界面打的键背后都是数字时，通话键拨出这串数字），页面上没有输入框时跳到这个字母开头的项（[18](18-nokia-form-factors.md) §4.2）；在输入框里：交给系统输入法；号码、数字框和 PIN 码里直接打出键上的数字，不用 Fn（[18](18-nokia-form-factors.md) §4.1） |
| 中 / 英切换键 | 全键盘：Ctrl+空格（诺基亚 E 系列的习惯；原型终端里也可按 F6）；九宫格：`#` |
| Chr / Sym | 打开系统符号表（九宫格用 `*`；原型终端里按 F7） |
| `/`（或专用键） | 命令面板：模糊搜索本页所有动作 + 全局命令 + 应用贡献的命令（打了字才列出，如设置的每一项） |
| 侧键 | 音量（闹钟响着时调的也是音量，闹钟跟着变轻变响，不稍后提醒）；看图 / 看视频时兼作缩放；只有电源键和音量键时，在电源菜单里移动选中项（见上面的电源键） |
| 两个音量键同时按 | 辅助功能快捷方式（安卓的做法）：放大、屏幕阅读器或颜色反转，按设置的选；一起按住到长按的时间朗读焦点所在的项；电脑终端里 Alt + F8、Alt + F9（[19](19-core-apps.md) §1.4） |

机身没有独立菜单键时，用「长按 OK」代替（B站 TV 版就是这么做的）。

**主屏宫格**：主屏是 3 列应用宫格，方向键二维移动；按数字键 1–9 直接打开对应位置的应用（诺基亚菜单宫格的做法），计算器的按键也是宫格。

**九宫格机身**：数字键 2–9 在输入框里输入拼音或英文（T9），0 上屏，1 分隔音节或打开标点，`#` 切换中 / 英 / 123；不在输入框时，数字键与全键盘字母一样用于快捷键或打字即搜索。原型用 `phone-shell --device bar-t9`（或 `--keypad t9`）模拟，按键细节见 [16](16-input-method.md) §2；与诺基亚各代机型的逐键对照见 [18](18-nokia-form-factors.md)。

## 2. 触屏手势 → 按键

| 触屏 | 含义 | 按键 | 先例 |
|------|------|------|------|
| 点按 | 主动作 | OK | 所有功能机 |
| 长按 | 次要动作 | 菜单键 / 长按 OK | S60 选项、BlackBerry 菜单键、B站 TV 版 |
| 右上角 ⋮ | 页面菜单 | 左软键「选项」 | S60 |
| 底部 Tab | 顶层分区 | 数字键 1–5 直达；或焦点移到 Tab 栏左右切 | |
| 左右滑切页 | 同级切换 | `Alt+←/→` | 桌面浏览器 |
| 下拉刷新 | 刷新 | `R`（菜单里也有） | |
| 左滑删除 | 删除 | `Del`（二次确认） | BlackBerry |
| 返回手势 | 返回 | 返回键 | |
| 双击点赞 | 快捷动作 | `L`（显示在菜单项右侧） | |
| 长按进入多选 | 批量操作 | 菜单「标记」/ `Shift+↑↓` | S60「标记 / 取消标记」 |
| 选中文本复制 | 文本选择 | 选择模式 + `Shift+方向` | BlackBerry |
| 拖进度条 | 跳转 | `←/→` ±10 秒；`0–9` 跳到 0–90% | YouTube 网页版 |
| 双指缩放 / 拖动 | 缩放平移 | `+/-` 或侧键；方向键平移 | |
| 点搜索框 | 搜索 | 直接打字 | BlackBerry 全局搜索 |
| 悬浮「+」按钮 | 创建 | 右软键 | |
| 按住说话 | 语音消息 | 按住专用键说话，松开发送（对讲机式） | |

全键盘相比遥控器是优势：B站 TV 版因为遥控器打不了字而不能发弹幕，全键盘机可以。

### 2.1 触摸屏：第二种输入（已实现，**未上真机**）

有触摸屏的整机（一加 6T：板子的 `[display] touchscreen`，[24](24-sku-framework.md) §7.4）上，触摸屏是第二种输入：它只换成按键，不另起一套界面，应用不知道有它。渲染器跟着一根手指，说它在画面的哪里、落在什么上（[23](23-renderer-protocol.md) §3 的 `touch`），Shell 认手势（`shell/touch.go`）。距离按逻辑像素算（6T 上一个是 0.28 mm）：

| 手势 | 等于 | 说明 |
|------|------|------|
| 点一行、一格 | 焦点移过去，再按 OK | 输入框只拿到焦点（OK 在输入框里是下一项或发送），打字照旧用键盘 |
| 点软键栏 | 左软键「选项」、OK、右软键 | 软键栏三等分，和鼠标指针一样 |
| 点标题栏 | 返回 | |
| 从左边缘（20 个逻辑像素以内，6T 上 5.6 mm：从侧面滑进来的手指要进来几毫米才摸得到）往右划，至少 24 个逻辑像素，横着比竖着远 | 返回 | 不管页面上是什么（宫格里的 ←、输入框里的光标），都是返回；全屏的浮层（取景框、扫码）和通知中心上也是 |
| 上下拖正文 | 滚动它 | 正文跟着手指走，松开停在那里（没有惯性）；焦点留在看得见的地方：它那一行（宫格里它那一排）出了画面，就换到那一边最近的整个看得见的一行（宫格里先找同一列）；比画面高的一项看得见一部分时焦点不动，它自己的滚动跟着手指。整页都看得见时拖动什么也不动（主菜单），选东西靠点。之后按键从焦点接着走，正文回到按键的滚法。渲染器没报这一页的排版时，和待机界面、菜单、对话框上一样，每 24 个逻辑像素一个 ↓ 或 ↑。从软键栏、标题栏、状态栏开始的拖动不算 |
| 左右划（至少 24 个逻辑像素，横着比竖着远） | → 或 ← | 往左划是 →（下一张、下一个值），往右划是 ←（上一张；普通列表里 ← 就是返回）。横着还是竖着在手指走出 `touchSlop`（8 个逻辑像素）时就定了：拇指划出的是一道弧，后半段可以往上偏 |
| 焦点在文本框上时左右拖 | 光标跟着手指走 | 手指每走 `touchCaret`（12 个逻辑像素，正文里约一个字宽）光标走一个字：往左拖光标往左，往右拖往右，和按 ← → 一样；拖着时就走，不等松开。页面和列表上的左右划不变（往左划是 →）。从左边缘开始的照旧是返回（2026-11-27，报告 008，**未上真机**） |
| 点进度条，或在上面左右划 | 那里的十分之一的数字键 | 页面绑了数字键（图片里的视频：0–9 跳到 0–90%，← → 退、进 5 秒）时才算；按十分之一跳，抬起手指时跳，不是拖着走 |
| 长按一行（不动，到设置 › 辅助功能的长按时间，默认 600 ms） | 焦点移过去，再按左软键 | 手指还按着菜单就出来；选项菜单先列这一行的动作：触屏的长按就是菜单键（§1） |
| 菜单、对话框里点一项、一个按钮、一格 | 选它 | 用浮层自己的键：方向键把选中的移过去，再按 OK；对话框里选中的那个是 OK，最后一个是返回（取消、拒绝、拒接、稍后提醒），中间的先用 ← → 选中（定位权限的「大致位置」）。每种浮层都能点，不用为触摸改哪一个 |
| 点菜单、对话框外面 | 返回 | 关掉菜单，取消对话框 |

规则：
- 触摸不点亮屏幕（在口袋里），屏幕暗着时不理；点亮靠电源键或按键。键盘锁着时只有浮层（来电、闹钟）理触摸，解锁照旧用键（左软键再按 `*`，或 PIN）；锁着时插上的 USB、蓝牙触摸屏到解锁为止连浮层也碰不到（[27](27-usb-typec.md) §2.1）。通话中（拨出、接通、保持）声音从听筒出来时，触摸照安卓的办法挡住脸颊：手机贴在耳边，又没有距离传感器把屏幕关掉（6T 的在 DSP 后面，[24](24-sku-framework.md) §7.4），脸会按到键。这时触摸什么也不按，响着的来电照旧能点「接听」「拒接」；按一下音量键，或手指不动按住屏幕一秒再松开，触摸打开 10 秒（最后一次触摸起算）；开了免提触摸照常。挂断用挂断键，有电源键、没有键盘的手机（6T）默认也能按电源键挂断（「按电源键挂断电话」），通话界面写着这台手机上怎么挂断（[19](19-core-apps.md) §5.6，**未上真机**）。
- 触摸换成的按键带着手指落下的时间：手指落下以后才弹出来的对话框不拿它当回答，对话框刚出来的半秒里也不（`shell/input.go`，和按键一样）；手指落下时最上面的浮层抬起时已经换了，这一下什么也不做。
- 返回（点标题栏、从左边缘划、返回键）一次退一步：应用的第一页上是回到打开它的系统界面（主菜单、文件夹、通知中心），不是待机界面；红键（挂断键）才一下回待机，和诺基亚一样。没有挂断键的整机（6T）上触摸只有返回。
- 应用在 ← → 的动作里换上的下一页（图片里的下一张）像进出一页那样滑进来：→ 从右边，← 从左边（[37](37-motion.md) §3）；设置 › 显示与亮度 › 动画效果不是「标准」时不滑。
- 每个拖动和划都在 Shell 的日志里记一行：`touch: swipe +31 × -4 px in 180 ms from the body: →`、`touch: drag … : scrolled from 0 to 120 of 300`、`… : nothing (all of the page shows)`，手机上没反应时看它认成了什么。
- 放大镜开着时（设置 › 辅助功能）渲染器不报触摸：手指下面不是帧上的那个位置（**未实现**）。只跟一根手指；双指缩放和多指手势、惯性滚动**未实现**。网页里直接点链接**未实现**：点网页等于把焦点移到它上面再按 OK。屏幕阅读器的触摸浏览（摸到哪读到哪）**未实现**。
- 屏幕上的九宫格（`shell/softkeypad.go`，报告 008 §1.3、§1.9）：只有触摸屏、没有能打字的键时（渲染器收触摸，报上来的键盘里没有一个有 OK 键：不接蓝牙键盘的 6T），焦点在输入框上，Shell 就在帧里带一块键盘（`keypad`，[23](23-renderer-protocol.md)），phone-paint 把它画在软键栏上面、四行各 34 个逻辑像素（6T 上约 9.5 mm 高），正文、候选栏照旧排在它上面；点一个键 phone-paint 报 `{"area": "keypad", "key": …}`，Shell 照键盘上的那个键按下，所以拼音、笔画、英文、Abc 多击、长按出数字、`*` 符号表、长按 `#` 切 123 都和实体九宫格一样，候选栏照旧。文字框是 1–9、`*`、0、`#` 加退格、← →、OK，数字下面写着这个输入法打出的字母（笔画模式是笔画，`#` 下面是现在的输入法）；数字框和密码框只有数字（实体九宫格在密码框里也只打数字），号码框多 `*`、`#`，按住 0 是 `+`，日期和时间框把 `*` `#` 换成 ↓ ↑（改这一段的数）。返回先收起键盘、焦点留在框上，再返回才退出；点这个框或焦点离开再回来，键盘又出来；有菜单、对话框盖着、键盘锁着、通话中不出来。接上有 OK 键的键盘（蓝牙）它就收起，键盘手机（矩阵键盘、QEMU 的 USB 键盘）上从来不出来。全键盘的整机（QWERTY 输入法）上文字框不出（只有数字框出），屏幕上的全键盘**未实现**；直接点候选栏里的字**未实现**（用 ← → 和 OK 选）；密码里的字母（实体九宫格也打不出）**未实现**。日志里每次换样子记一行 `keypad: "digits"`。

## 3. 七条硬规则（由系统强制，不靠应用自觉）

1. **没有只能靠手势触发的功能。** 每个可操作元素都声明动作列表：一个主动作（OK），其余进上下文菜单。
2. **页面菜单分三组**：焦点元素 / 本页 / 全局。快捷键写在菜单项右侧，用户从菜单里学会快捷键（桌面软件的老办法）。
3. **菜单最多两级**；更深就拆成独立页面。
4. **返回永远可用**，并回到原位置（列表滚动位置、输入草稿都保留）。
5. **打字即搜索**；命令面板能搜到本页所有动作。
6. **焦点永远可见**（高对比焦点框）；焦点顺序 = 阅读顺序。
7. **底部常驻一行软键标签**，随焦点变化（S60 风格），用户随时知道左右软键此刻做什么。

## 4. 语义 UI 模型 `phone.Ui`（v0 已在原型实现）

应用不自己画界面，只交出一棵「内容 + 动作」的树；Shell 负责焦点、按键、菜单和渲染。

> **原型实现**：类型定义在 [ui/proto.go](../ui/proto.go)，能力目录在 [ui/caps.go](../ui/caps.go)。与下面草案的不同：v0 节点为 `text / section / item / input / button / image / media / doc / progress`（`media` 即草案的 `MediaSurface`，已实现；`doc` 是 Markdown 文档，链接自动变成 `link:N` 菜单动作；`progress` 是进度条；`Grid` 由 `Screen.Columns` + `tile` 项实现）；`item` 带 `style: bubble-in / bubble-out` 表示聊天气泡；`input` 带 `keyboard: number / phone / email` 指定键盘类型；传输用 JSON 行（不是 §4.4 的二进制）；能力请求（`req / res`）走同一连接。§3 的七条规则中，1–5、7 已由 Shell 强制实现，规则 6 的焦点框已实现。

### 4.1 节点 v0

| 节点 | 用途 | 文本渲染器里 |
|------|------|--------------|
| `Screen` | 标题、软键、主体 | 顶栏 + 底栏 |
| `List` / `Grid` | 列表、九宫格 | 列表；网格逐行列出 |
| `Item` | 一条内容：头像 / 缩略图、主标题、副标题、角标、**动作列表** | 一到两行文字 |
| `Text` | 富文本，可内嵌表情、链接、小图 | 表情降级为 `[doge]`，图降级为 `[图]` |
| `Image` | 缩略图、头像、大图 | `[图]` |
| `MediaSurface` | 视频、相机预览、PDF 页（画面由媒体服务提供） | `[视频 03:12 ▶]` + 播放控制 |
| `Form` | 输入框、开关、单选、多选 | 原生表单 |
| `Menu` / `Dialog` / `Toast` | 由 Shell 根据动作列表生成，应用不直接画 | 弹出层 |

### 4.2 动作

```
Action {
  id:      "reply"
  label:   "回复"
  key:     "R"        # 可选快捷键，显示在菜单项右侧
  primary: false      # true = OK 键执行；每个 Item 至多一个
  group:   "item"     # item | page | global | danger
  confirm: false      # danger 组默认二次确认
}
```

### 4.3 示例：一条评论

```
Item {
  id: "c123"
  leading:   Image(avatar://u42, 32x32)
  primary:   "某某"
  secondary: Text["说得对 ", Emoji("doge")]
  media:     [Image(thumb://p9)]
  trailing:  "128 赞"
  actions: [
    { id: "open",   label: "查看回复", primary: true },
    { id: "reply",  label: "回复",     key: "R" },
    { id: "like",   label: "点赞",     key: "L" },
    { id: "copy",   label: "复制",     key: "C" },
    { id: "report", label: "举报",     group: "danger" }
  ]
}
```

### 4.4 实现约束

- **传输**：D-Bus 只用于系统服务的控制面；界面树走 Unix socket + 紧凑序列化 + 增量更新（D-Bus 不适合频繁的大消息）。
- **图片不进消息体**：只传引用（文件路径 / 共享内存 / dmabuf），由 Shell 或媒体服务解码、缓存。
- **应用崩溃不影响 Shell**：每个应用独立进程，Shell 显示「应用无响应」并可重启它。
- **v0 做了** `Screen / List / Item / Text / Image / Form / Menu`；`Grid`（`Screen.Columns` + `tile`）、`MediaSurface`（`media` 节点）也在 v0 里（见 §4 开头）。
- 先例：Android RemoteViews（桌面小部件）、早期 WatchKit（App 跑在手机上、界面显示在手表上）、服务端驱动 UI。

## 5. 走查：用 B站 / 微信的界面结构检验语法

> 只借这两个 App 的**界面结构**检验交互是否够用，不代表开发它们的客户端（见 09 §5）。
> 示意屏：480×640 竖屏，正文约每行 20 个汉字、20 行左右。

### 5.1 B站式：推荐流 → 视频页 → 评论

推荐流（像素渲染）：

```
┌ 推荐 │ 热门 │ 动态 │ 我的 ─────────┐  ← 1–4 直达 Tab
│ ┌──────┐ 【4K】某纪录片 第3集       │
│ │ 缩略 │ UP 某某 · 12.3万播放        │  ← 焦点
│ └──────┘                            │
│ ┌──────┐ 三分钟看懂 RK3566          │
│ │ 缩略 │ UP 某某 · 8.1万播放         │
│ └──────┘                            │
│ ...                                 │
├─────────────────────────────────────┤
│ 选项           OK 播放          搜索 │
└─────────────────────────────────────┘
```

| 用户想做 | 手机上 | 这里 |
|----------|--------|------|
| 打开视频 | 点卡片 | OK |
| 稍后再看 / 不感兴趣 / 分享 | 长按卡片或点 ⋮ | 菜单键 → 列表；或快捷键 `W` / `X` |
| 进 UP 主主页 | 点头像 | 菜单键 →「UP 主主页」，或 `U` |
| 刷新 | 下拉 | `R` |
| 搜索 | 点搜索框 | 直接打字 |

视频页：上方 `MediaSurface`（16:9，约 480×270），下方「简介 / 评论」两个 Tab。

| 用户想做 | 这里 |
|----------|------|
| 播放 / 暂停、快进 | 焦点在视频上：OK、`←/→` |
| 弹幕开关 / 发弹幕 | `D` / `T`（底部弹出输入行，全键盘打字） |
| 点赞 / 投币 / 收藏 / 三连 | `L` / `C` / `F` / 菜单里「三连」 |
| 清晰度、倍速 | 左软键「选项」 |
| 全屏 | `Z` |
| 回复某条评论 | 焦点移到该评论 → `R` |

同一页在文本渲染器里：缩略图变 `[图]`，视频变 `[视频 12:31 ▶]`。评论区完全可用，首页推荐流明显变差——这就是 09 §1 说的「渲染层瓶颈」。

### 5.2 IM 式：会话列表 → 聊天

| 微信里的操作 | 这里 |
|--------------|------|
| 长按会话：置顶 / 标为未读 / 删除 | 菜单键 |
| 搜人 | 在会话列表直接打字 |
| 聊天页打字 | 默认焦点在输入框，直接打字，Enter 发送 |
| 翻看历史消息 | `↑` 把焦点移进消息区，逐条移动 |
| 长按消息：复制 / 转发 / 引用 / 多选 / 删除 | 焦点在消息上按菜单键（与微信的长按菜单一一对应） |
| 发图片 | 菜单「附件 → 相册」，九宫格用方向键选，OK 发送 |
| 看大图 | 焦点在图片上按 OK → 全屏查看器，`←/→` 换张，`+/-` 缩放 |
| 语音消息 | 按住专用键说话，松开发送 |
| 朋友圈九宫格 | 像素端正常显示；文本端只剩 `[图×9]` |
| 公众号文章、小程序、支付 | **不支持**（需要浏览器引擎与厂商，见 [09](09-ui-feasibility-review.md)） |

结论：两个样本里，交互层的每个入口都能映射到按键，没有发现做不到的；做不好的全部集中在渲染层（缩略图流、九宫格）和生态层（H5、小程序、支付）。

## 6. 屏幕信息量估算

| 屏 | 正文字号 | 每行汉字 | 行数（不含状态栏 / 软键栏） |
|----|----------|----------|------------------------------|
| 2.4" 320×240 横屏（约 167 ppi） | 16 px | ~20 | ~11 |
| 2.8" 640×480 横屏（约 286 ppi） | 26 px | ~24 | ~15 |
| 3.5" 480×640 竖屏（约 229 ppi） | 24 px | ~20 | ~20 |

带缩略图的列表项每屏约 3–5 条，与 B站手机版一屏的条数相近。真正受限的是分屏：任何一种屏切成两半，每格每行只剩约 10 个汉字，所以不做通用平铺（09 §3.3）。

## 7. 按键做不好的场景

| 场景 | 原因 | 处理 |
|------|------|------|
| 地图自由拖动 | 连续二维操作 | 以搜索 / 路线列表为主，方向键平移；画布应用 |
| 网页自由浏览 | 页面不是为焦点设计的 | 阅读模式 + 链接列表；必要时虚拟光标（KaiOS 的做法） |
| 游戏、绘图、图片编辑 | 连续输入 | 画布应用，或不做 |
| 小程序 / H5 应用 | 需要浏览器引擎 + 厂商 | 不做 |
