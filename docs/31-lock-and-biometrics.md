# 锁屏与生物识别：锁屏 PIN 码、指纹解锁、指纹支付

> 状态：**原型 ✓（开发机）**。锁屏 PIN 码、息屏即锁、锁屏上的紧急呼叫和隐藏通知内容、指纹录入和解锁、连续失败停用、指纹支付和录入新指纹后支付密钥作废，在开发机自测的 9 个用例里通过（文本和像素渲染器都跑过）；`keystore`、`hal/fingerprint` 单元测试 ✓。指纹传感器是**模拟的**；真机传感器**未实现**（依赖硬件和厂商的 TEE，见 §4.1）；模板、匹配和令牌放进 TEE **未实现**（R15），现在由 phone-keystored 代替。QEMU 上没有跑（由负责人跑），未上真机。

## 0. 结论

- 没设锁屏 PIN 码时一切照旧：键盘锁是诺基亚式的，按左软键再按 `*` 就解开，不需要秘密。
- 在「设置 › 安全」设了 PIN 码（4 到 16 位数字）后，键盘锁变成安全锁，做法和 Android、iOS 一样：息屏就锁（可以设宽限时间），开机也是锁着的；锁屏挡住原来在前台的应用，通知只显示应用名和条数（可以在设置里打开内容）；只有 PIN 码或录入的指纹能解开。
- 锁着也能做的事：拨紧急号码、接听来电、关闭闹钟；NFC 的门禁卡和快捷交通卡息屏、锁着时不按键就能刷，连按两下电源键打开快速选卡（[30](30-nfc.md) §5）。别的功能可以在锁屏上加自己的快捷键（§2.3）。
- PIN 码只在系统界面上输入，交给 phone-keystored 校验：存的是加盐的慢哈希（PBKDF2，叠加由设备密钥派生的密钥），PIN 码本身不落盘、不进日志，Shell 也不留；连续输错 5 次要等 30 秒，错得越多等得越久，重启也不清零。
- 指纹走 `hal/fingerprint`：开发机和 QEMU 上是模拟传感器，自测用 `finger <名字>` 碰它。模板和匹配在 phone-keystored 里（TEE 的替身），匹配成功只给出一个认证令牌（照 Android 的 HardwareAuthToken），Shell 只负责转交。
- 指纹支付：`auth.confirm` 多了 `bio_key`，绑定指纹的密钥只在指纹匹配后签名，录入或删除指纹后作废（iOS 的 biometryCurrentSet、Android 的 setInvalidatedByBiometricEnrollment）；系统确认框写「触碰指纹传感器确认，或输入支付密码」，签名照旧覆盖显示的文字，服务端照旧用 `keystore.VerifyConfirm` 验签。

## 1. 和 Android、iOS 对照

| 方面 | Android | iOS | 本平台 |
|------|---------|-----|--------|
| 锁屏凭据 | PIN、图案、密码，由 Gatekeeper（TEE）校验，失败后按次数退避 | 密码，由 Secure Enclave 校验，失败后逐级等待 | 4–16 位 PIN 码，由 phone-keystored 校验（TEE **未实现**，R15），5 次后 30 秒，之后更长，重启不清零 ✓ |
| 什么时候锁 | 息屏后（可设延迟）、开机 | 息屏后（可设「需要密码」的时间）、开机 | 息屏后（立即、5 秒、30 秒、1 分钟、5 分钟）、开机 ✓ |
| 锁着能做什么 | 紧急呼叫、接电话、关闹钟、锁屏快捷方式 | 同左 | 同左；锁屏快捷键给系统功能用（§2.3）✓ |
| 锁屏通知 | 可隐藏敏感内容 | 默认「解锁后显示预览」 | 默认只显示应用名和条数，设置里可显示内容 ✓ |
| 指纹数量 | 一般最多 5 个 | Touch ID 最多 5 个 | 最多 5 个 ✓ |
| 模板放在哪 | TEE 里的指纹 TA | Secure Enclave | phone-keystored 里，落盘时用设备密钥派生的密钥加密（TEE **未实现**） |
| 失败次数 | 5 次后 30 秒，20 次后要凭据 | 5 次后要密码 | 连续 5 次后停用，要 PIN 码 ✓ |
| 何时必须用凭据 | 重启后、72 小时没用过凭据等 | 重启后、48 小时没解锁过等 | 重启后、48 小时没输 PIN 码 ✓ |
| 删除凭据 | 指纹一并删除 | 同左 | 同左 ✓ |
| 支付里的生物识别 | BiometricPrompt + CryptoObject，密钥可设成录入新指纹后失效 | LocalAuthentication + SecAccessControl（biometryCurrentSet） | `auth.confirm{bio_key}`，绑定指纹的密钥，指纹集合变了就作废 ✓ |
| 认证令牌 | HardwareAuthToken（HMAC，每次开机换密钥） | Secure Enclave 内部 | 同 Android 的格式和规则（§4.3）✓ |

## 2. 锁屏

### 2.1 什么时候锁

`c.keylock` 是唯一的锁状态，`c.locked()` 是它的判断；PIN 码只决定怎么解开（`c.secureLocked()`）。

| 情况 | 没设 PIN 码 | 设了 PIN 码 |
|------|-------------|-------------|
| 待机界面左软键再按 `*` | 键盘锁 | 安全锁 |
| 自动键盘锁（设置 › 键盘锁） | 键盘锁 | 安全锁 |
| 息屏 | 不锁（和以前一样） | 过了宽限时间就锁（默认立即）：「立即」在息屏的同一次例行检查里就锁上；宽限时间按息屏时 5 秒一次的例行检查算，按键唤醒前先补查一次 |
| 开机、Shell 重启 | 不锁 | 锁；Shell 先按记下的状态锁上，再听 phone-keystored 的 |

安全锁锁上时，Shell 关掉屏幕上的菜单和对话框（来电、闹钟、SIM 卡 PIN 码界面留着），把前台应用和待机之上的系统页面藏起来，只留待机界面；解锁后原样还回去。

### 2.2 锁着能做什么

| 按键或事件 | 安全锁 |
|------------|--------|
| 数字键、OK、左软键 | 叫出 PIN 码界面（数字键直接算第一位） |
| 通话键 | PIN 码界面上打的是紧急号码（112、110、119、120、122、911、999）时直接拨出，不用解锁；打的数字不显示，PIN 码开头像紧急号码也不泄露。锁屏上直接按通话键也叫出这个界面 |
| 指纹 | 录入过的手指解锁（息屏时一碰也先点亮屏幕）；认不出提示「未能识别指纹」 |
| 来电 | 系统接听界面照常；接通后只有通话界面能用，菜单、任务切换、返回这些出不了通话界面；挂断后回到锁屏 |
| 闹钟 | 照常响，照常关 |
| 通知 | 待机界面只写「飞钱：1 条通知」这样的应用名和条数，横幅只写应用名；设置里打开「锁定时显示通知内容」后照常显示 |
| 挂断键 | 回到锁屏（紧急电话打完后）；没有电源键的机型在锁屏上停一下再连按两下：快速选卡（[18](18-nokia-form-factors.md) §5.1） |
| 电源键 | 息屏、亮屏（息屏照 §2.1 的规则上锁）；连按两下打开快速选卡，盖在锁屏上，不用解锁，选的卡出示 60 秒，付款卡要先解锁（[30](30-nfc.md) §5）；按住打开电源菜单 |

### 2.3 锁屏快捷键（给其他功能用）

锁屏上可以加不用解锁就能用的系统功能（比如手电筒）。列在 `shell/lock.go` 的 `lockShortcuts` 里，一个功能加一行，可以写在自己的文件的 `init` 里。现在没有功能注册：NFC 原来的 → 快捷键去掉了，卡不用按键就能刷，快速选卡由电源键打开（[30](30-nfc.md) §5）。

```go
lockShortcuts = append(lockShortcuts, lockShortcut{Key: KeyF2, Label: "Torch", Run: (*Core).torch})
```

规则：`Run` 被调用时手机还锁着，只能弹出系统的弹层，别的都在锁后面；`Label` 写英文，锁屏提示里翻译后显示。锁屏自己占用的键：数字、OK、左软键、`*`、通话键、挂断键、返回（电源键不经过锁屏）；空着的是右软键和方向键。

## 3. PIN 码

| 环节 | 做法 |
|------|------|
| 设置、修改、删除 | 设置 › 安全；PIN 码在系统自己的界面上输入（设置应用调 `settings.set lock_pin`，回复等用户办完），设置应用拿不到；修改要先输现在的，新的输两遍；删除要输现在的，指纹一并删除 |
| 保存 | phone-keystored 的 `keystore/lock.json`：随机盐、PBKDF2-SHA256（10 万轮）、算前先用设备密钥派生的密钥做 HMAC（文件拿到别的设备上没用；量产换成 TEE 的硬件密钥）；还有「安全用户 ID」，设 PIN 码时生成，令牌里带着它 |
| 不留明文 | PIN 码只在系统界面里打到一半时在 Shell 内存里，交出去就清掉；不写盘、不进日志 |
| 输错 | 连续 1–4 次：提示还能错几次；5–9 次：每次之后等 30 秒；10–14 次 1 分钟；15–19 次 5 分钟；20–29 次 30 分钟；30–39 次 1 小时；之后 1 天。次数写在 `lock.json`，重启后从头再等一遍当前的时长（不会因为重启变短） |
| 和支付密码的关系 | 锁屏 PIN 码和可信确认里的支付密码是两样东西（像支付宝的支付密码和手机锁屏密码）；合成一个是以后的取舍，**未实现** |

## 4. 指纹

### 4.1 HAL 与传感器

`hal/fingerprint` 定义 `Sensor`：`Capture` 等一次触碰并读出特征，`Enroll` 开始录入（`Add` 一次次加触碰、报进度，够了给出模板），`Match` 比对特征和模板。整个包只在 phone-keystored 里用，读数和模板出不了这个进程。

| 后端 | 状态 |
|------|------|
| 模拟（`Sim`，开发机和 QEMU） | ✓：每个名字是一根不同的手指，每次触碰读数略有不同；录入要碰 5 次，换了手指不算；自测命令 `finger <名字>` 经 Shell 交给 phone-keystored（`fp.sim_touch`，和模拟基带的 `sim.ring` 一样，是测试钩子） |
| 手机上的 SPI 传感器（FPC、汇顶） | **未实现**，依赖硬件：主线内核没有驱动，厂商在 TEE 的可信应用里驱动它，录入和比对也在那里做，所以后端是那个可信应用的客户端，要厂商的 TEE。测试机红米 Note 4X 是 FPC 的传感器，没有主线驱动 |
| USB 传感器（libfprint 支持的） | **未实现**；libfprint 是 LGPL，只能放在单独的进程里，后端经进程间接口和它说话，不能链接进平台 |
| 没有可用传感器的机型 | 主板配置不写 `fingerprint`（[24](24-sku-framework.md)），phone-keystored 就没有传感器，设置里写「没有指纹传感器」 |

phone-keystored 的后端按主板配置（`sku.json` 的 `fingerprint`）选：模拟器的主板写 `sim`，真机的主板在传感器有驱动之前不写，就没有指纹；没有 `sku.json` 的开发机用模拟后端；`--fingerprint` 可以改。真机上传感器的中断应当是唤醒源，碰一下就从挂起里醒来（**未实现**）；开发机上 `finger` 命令先点亮屏幕。

### 4.2 模板与匹配（keystored 代 TEE）

| 环节 | 做法 |
|------|------|
| 录入 | 先在系统界面输一次 PIN 码：phone-keystored 发一个挑战，PIN 码校验通过给出带这个挑战的令牌，录入要这个令牌，10 分钟内有效（Android 的做法）；然后系统的录入界面按进度一格格点亮，碰到已经录过的手指提示换一个 |
| 保存 | `keystore/fingerprints.json`：名字和模板，模板用设备密钥派生的密钥（AES-GCM）加密；还有「指纹集合 ID」，每次增删指纹都换一个 |
| 比对 | 只在 phone-keystored 里；成功给令牌，不给模板也不给读数 |
| 改名、删除 | 设置 › 安全 › 指纹（进来要先输 PIN 码）；删除也要那个令牌 |

### 4.3 认证令牌

照 Android 的 HardwareAuthToken：PIN 码校验和指纹比对各出一个，要用户在场的操作（录入指纹、用绑定指纹的密钥签名）收它。MAC 的密钥在 phone-keystored 每次启动时随机生成，只有它能出、能验，重启后旧令牌全部失效；Shell 只转交。

```
版本(1) | 挑战(8) | 安全用户 ID(8) | 认证者 ID(8) | 类型(4：1 PIN、2 指纹) | 时间(8：启动后的毫秒) | HMAC-SHA256(32)
```

### 4.4 规则

| 规则 | 做法 |
|------|------|
| 最多 5 个指纹 | 第 6 个录不进 |
| 连续 5 次认不出 | 指纹停用，锁屏提示要 PIN 码；输对 PIN 码后恢复（解锁和支付共用这个计数） |
| 重启后 | 第一次解锁要 PIN 码（phone-keystored 启动后还没见过 PIN 码时拒绝指纹） |
| 48 小时没输 PIN 码 | 同上 |
| 删除 PIN 码 | 指纹全部删除，绑定指纹的密钥随之作废 |
| 用途开关 | 设置 › 安全 › 指纹：「解锁手机」（默认开）、「支付」（默认关） |

## 5. 指纹支付

1. 应用调 `auth.confirm{key, bio_key, prompt, payload}`（飞钱：`key: "pay"`、`bio_key: "pay-bio"`）。用户打开了「指纹用于支付」并且录了指纹时，系统确认框写「触碰指纹传感器确认，或输入支付密码」，同时等指纹和支付密码。
2. 指纹匹配：phone-keystored 先核对 `bio_key` 这把密钥还在、绑的是当前的指纹集合，再等触碰；匹配后给一个只对这把密钥这一次签名有效的令牌（30 秒内）；Shell 把令牌转给 `confirm_bio`，密钥对「显示的文字 + 载荷」签名。证明里 `key_alias` 是 `pay-bio`、`bio: true`。
3. 支付密码：和以前一样用 `key` 签名；签完 phone-keystored 顺带把 `bio_key` 做出来（没有、或者已经作废时），绑到当前的指纹集合。所以绑定指纹的密钥**只在支付密码确认之后**才会生成：知道锁屏 PIN 码的人录了自己的指纹，旧密钥作废，他也付不了款。
4. 录入或删除指纹后：确认框说明「开通指纹支付后指纹有变动，请用支付密码确认，指纹支付随之重新开通」，只收支付密码；确认后新密钥生成，下一次又能用指纹。第一次用也是这样（「先用支付密码确认一次，之后就能用指纹支付」）。
5. 服务端（飞钱里的模拟商户）照旧用 `keystore.VerifyConfirm` 逐级验签：厂商根 → 设备证书 → 应用密钥证书 → 签名 → 内容核对。绑定指纹的密钥的证书写明它是「指纹绑定」（`keystore.AppKeyCertMsgBio`），`VerifyConfirm` 按证明里的 `bio` 选证书格式，所以服务端知道这次是指纹确认的；飞钱收 `pay` 和 `pay-bio` 两把。

| 密钥 | 怎么确认 | 证书里写的 |
|------|----------|-----------|
| `key`（如 `pay`） | 支付密码 | `user_auth` |
| `bio_key`（如 `pay-bio`） | 指纹，匹配后 30 秒内、只用一次 | 指纹绑定；指纹集合一变就作废 |

小程序宿主照旧只传 `key`，不受影响。

## 6. 设置 › 安全

| 项 | 做法 |
|----|------|
| 锁屏 PIN 码 | 设置、修改、删除，都在系统界面输入（`settings.set` 的 `lock_pin`：1 设置或修改，0 删除） |
| 息屏后多久锁定 | 立即、5 秒、30 秒、1 分钟、5 分钟（`lock_grace`，秒） |
| 锁定时显示通知内容 | 开关（`lock_show_content`） |
| 指纹 | 进来先在系统界面输 PIN 码（`fingerprint_auth`）；列出指纹，改名（`fingerprint_rename`，值是 ID，`text` 是名字）、删除（`fingerprint_delete`）；添加（`fingerprint_enroll`，系统的录入界面）；「解锁手机」「支付」两个开关（`fingerprint_unlock`、`fingerprint_pay`） |

`settings.get` 的 `security` 里有：是否设了 PIN 码、宽限时间和选项、是否显示通知内容、传感器、指纹列表（只有 ID 和名字）、最多几个、两个开关、指纹为什么暂时不能用（`restart`、`timeout`、`lockout`）。设置应用的代码在 `apps/settings/security.go`，Shell 这边在 `shell/lock.go`、`shell/lockpad.go`、`shell/biometric.go`。

## 7. 接口

phone-keystored 的方法（只有 Shell 调，`keystore/methods.go`）：

| 方法 | 做什么 |
|------|--------|
| `lock.status` | PIN 码、等待、传感器、指纹列表、为什么要 PIN 码 |
| `lock.set_pin` / `lock.clear_pin` / `lock.verify` | 设置或修改、删除、校验 PIN 码；校验带挑战，对了给令牌 |
| `fp.challenge` / `fp.enroll` / `fp.enroll_next` | 录入：挑战、开始（要 PIN 令牌）、等下一次触碰并报进度 |
| `fp.auth` | 等一次触碰并比对；带 `app`、`key` 时是为那把绑定指纹的密钥签名 |
| `fp.cancel` | 结束等待（和录入） |
| `fp.rename` / `fp.remove` | 改名、删除（删除要 PIN 令牌） |
| `confirm` 的 `bio_key` / `confirm_bio` | 支付密码确认后做出绑定指纹的密钥；拿指纹令牌用它签名 |
| `fp.sim_touch` | 模拟传感器的测试钩子 |

## 8. 测试

| 环境 | 结果 |
|------|------|
| 单元测试（`keystore`） | PIN 码格式、慢哈希不含明文、改 PIN 码要旧的、5 次后 30 秒、10 次后 1 分钟、重启后等待不变短、对了清零；令牌被改、跨重启都无效；录入要新的 PIN 令牌（过期的不行）、换手指和录过的手指被拒、最多 5 个、改名、删除要令牌；比对：5 次失败停用、PIN 码恢复、48 小时、重启后要 PIN 码、模板跨重启可用；删 PIN 码删指纹；取消等待；绑定指纹的密钥：没 PIN 确认前没有、签名能过 `VerifyConfirm`、令牌只能用一次、解锁的令牌不能签名、支付密码签不了它、当成普通密钥验不过、录新指纹后作废并能重新生成、30 秒后令牌过期 ✓ |
| 单元测试（`hal/fingerprint`） | 录入的手指 200 次都能匹配、别的手指 200 次都不匹配；录入拒绝换手指；等待触碰；刚好在等待前的触碰算数、过期的不算 ✓ |
| 开发机自测（`--only '^锁屏'`，文本和像素渲染器） | 9 个用例 ✓：设置 PIN 码；指纹页先要 PIN 码、录入 5 次（换手指不算）、打开指纹支付；息屏即锁、锁屏挡住计算器、手指一碰解锁并回到计算器；锁屏只显示「飞钱：1 条通知」；陌生手指 5 次后停用、输错 PIN 码有提示、输对解锁；锁着拨 112；飞钱第一次用支付密码开通、第二次指纹付款并通过商户验签；再录一个指纹后退回支付密码、确认后新录的手指也能付；删除 PIN 码后恢复键盘锁 |
| QEMU、真机 | 没有跑（QEMU 由负责人跑；真机没有指纹驱动） |

## 9. 没做的

| 项 | 说明 |
|----|------|
| 放进 TEE（R15） | PIN 码校验、模板、比对、令牌密钥都该在 OP-TEE 的可信应用里，PIN 码经可信输入路径进去；现在是 phone-keystored 进程 |
| 真机指纹传感器 | 见 §4.1：FPC、汇顶要厂商 TEE；USB 传感器经 libfprint 的单独进程；都**未实现** |
| 传感器唤醒挂起 | 真机上传感器中断做唤醒源，**未实现** |
| 锁屏上回到通话 | 安全锁下在通话界面按了挂断键以外的离开方式，回到锁屏后不能直接回通话界面（要解锁），**未实现** |
| IFAA / SOTER | 支付宝、微信的生物认证标准对接，**未实现**（要厂商 TEE 和认证） |
| 人脸、图案、密码 | 只有数字 PIN 码和指纹 |
| 锁屏 PIN 码和支付密码合一 | 见 §3，**未实现** |
